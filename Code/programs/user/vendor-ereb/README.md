# vendor-ereb — закреплённая копия крейтов ereb

Терминал VOID строится на крейтах проекта **ereb** (апстрим — отдельный репозиторий владельца,
`~/Project/Rust/ereb`): решение записано в [[0014-terminal-ereb]], там же — почему переносятся
крейты, а не бинарь.

**Закреплено на коммите ereb `3a1d5db`.**

Здесь, а не в `vendor/`, по технической причине: `vendor/` объявлен подменой источника crates.io
(`.cargo/config.toml`), и cargo требует от каждого каталога там реквизитов реестра
(`.cargo-checksum.json`). Эти крейты приходят не из реестра, поэтому лежат рядом и подключаются
как path-зависимости.

## Правило

Править **в апстриме**, сюда переносить осознанно — ровно та же дисциплина, что со smoltcp и
rustls: сборка VOID обязана оставаться оффлайн и воспроизводимой, поэтому path-зависимости на
соседний каталог вне репозитория недопустимы.

Что здесь лежит:

| крейт | что делает | зачем VOID |
|---|---|---|
| `ereb-core` | грид ячеек + разбор ANSI (поверх `vte`) | модель экрана терминала |
| `ereb-render` | палитра, кэш глифов, blit, растеризатор `ttf` | превращает грид в пиксели |
| `ereb-input` | клавиша → действие, кодирование в PTY | ввод (пока частично) |
| `ereb-mux` | дерево разбиений, раскладка панелей, навигация | мультиплексор |

Все три собираются `no_std` + `alloc` — у VOID нет ни libc, ни std в этих программах.

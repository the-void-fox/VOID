# vendor-lzma — закреплённая копия распаковщика xz

Пакеты бинарного кэша nixpkgs лежат в виде `.nar.xz` — сжатыми. Чтобы VOID могла ставить пакеты
сама ([[0009-ondevice-packages]], Фаза 8), ей нужен распаковщик xz **на устройстве**, в программе
без std и без libc.

Здесь лежит **`lzma-rs` 0.3.0** (Guillaume Endignoux, MIT) — чистый Rust, апстрим
<https://github.com/gendx/lzma-rs>.

Здесь, а не в `vendor/`, по той же технической причине, что и `vendor-ereb/`: `vendor/` объявлен
подменой источника crates.io, и cargo требует от каждого каталога там реквизитов реестра
(`.cargo-checksum.json`). Копия **изменена**, реквизитам реестра она соответствовать не может и не
должна — поэтому подключается path-зависимостью.

## Что изменено

| было | стало | почему |
|---|---|---|
| `std` | `no_std` + `alloc` | в программах VOID нет ни std, ни libc |
| `encode/`, `decode/stream.rs` | удалены | сжимать нам нечего, а `stream` глубже всех врос в `std::io` |
| `std::io` | `src/io.rs` — свой шим | вход распаковки у нас слайс, выход `Vec<u8>`; ни файлов, ни дескрипторов |
| крейт `byteorder` | `src/byteorder.rs` | четыре метода чтения целых |
| крейт `crc` | `src/crc.rs` | CRC-32/ISO-HDLC и CRC-64/XZ, таблицы считаются в `const fn` |

**Зависимостей у копии не осталось ни одной** — это осознанно: `byteorder` и в дереве VOID есть,
но он приходит как зависимость сетевого стека, и унификация фич однажды включила бы ему `std`.

**Тела декодеров не тронуты.** Правился только их контакт с внешним миром: `use`-строки, типы
читателя и писателя. Правило то же, что со smoltcp, rustls и ereb — подменять границу, а не тело,
иначе следующее обновление апстрима превращается в переписывание.

Шимы повторяют семантику `std` там, где от неё зависит результат: ёмкость `BufReader` = 8192 (по
ней декодер xz считает, сколько байт попало под CRC заголовка блока), `Take::fill_buf` обрезает по
остатку лимита, `read_exact` при нехватке даёт `UnexpectedEof`.

## Проверка

`cargo test -p lzma-rs` — контрольные значения CRC из каталога RevEng и распаковка настоящего
`.xz`, собранного `xz -9` (фикстуры в `lzma-rs/tests/`). Плюс сквозная проверка на самой VOID:
`nar-unpack` принимает `.nar.xz` и раскладывает пакет в store.

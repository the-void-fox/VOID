# acpi-srv — исполнение AML на VOID (Веха 236)

Наша сторона границы с [uACPI](../../../vendor/uacpi) — чужим проверенным интерпретатором AML,
взятым по [ADR 0025](../../../Obsidian/10-projects/void/adr/0025-aml-foreign-interpreter.md).

## Три файла и зачем они разделены

| файл | что делает |
|---|---|
| `glue.c` | сорок функций `uacpi_kernel_*`: память, журнал, часы, порты, PCI, замки, отложенная работа |
| `tables.c` | отдать библиотеке таблицы прошивки, не имея права на физическую память |
| `main.c` | подъём и ПРОБА: найти батарею, крышку и адаптер по идентификаторам, спросить их |

Разделены по границам ответственности: `glue.c` — наша плата за чужой код, `tables.c` — леса
вокруг недостающего права, `main.c` — то, ради чего всё.

## Собрать

```
nix-build nix -A x86_64.acpi_srv
nix-build nix -A riscv64.acpi_srv
```

Обе архитектуры, `-Wall -Wextra`, без предупреждений. Выходит статический ELF ~310 КиБ.

## Права (позиционно, как во всей системе)

```
service acpi-srv hwprobe ioport:ec
```

- **0 — `hwprobe`**: таблицы прошивки (`SYS_ACPI_TABLE`), порты, конфигурация PCI;
- **1 — `ioport:ec`**: узкое право на порты встроенного контроллера, если прошивка их объявила.

## Чего ещё НЕТ — названо вслух, а не спрятано

1. **Отображение физической памяти.** Областям AML вида `SystemMemory` (у X54C это NVS
   прошивки и десятки окон поменьше) нужна настоящая физическая память; наше право на окно
   выдаётся под устройство с шины. Нужен узкий вид права «страницы, объявленные прошивкой» —
   карту памяти ядро видит и может его проверить. До тех пор такие области отвечают ОТКАЗОМ,
   а не нулями: нули из NVS означали бы «графики нет, батареи нет» — правдоподобно и неверно.
2. **Прерывание SCI.** Через него приходят события: крышка, кнопка сна, сообщения контроллера.
   `SYS_IRQ_WAIT` у нас есть, не хватает выдачи IRQ-права по вектору из FADT.
3. **Обработчик области `EmbeddedControl`.** uACPI его не содержит и не должна: драйвер
   контроллера — работа операционной системы. Рукопожатие по статусному порту, чтение, запись,
   очередь запросов `_Qxx`.
4. **Доставка в образ.** Выкладка собранных C-программ (`stage-drivers.sh`) сейчас описана
   форматом `drivers.list`, рассчитанным на портированные драйверы Linux; `acpi-srv` в него не
   ложится. Пока не доставлен — на машине не запускался.

Пункты 1 и 4 держат всё остальное: без первого методы читают не ту память, без четвёртого
программу некуда положить.

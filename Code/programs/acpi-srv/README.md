# acpi-srv — исполнение AML на VOID (Веха 236)

Наша сторона границы с [uACPI](../../../vendor/uacpi) — чужим проверенным интерпретатором AML,
взятым по [ADR 0025](../../../Obsidian/10-projects/void/adr/0025-aml-foreign-interpreter.md).

## Три файла и зачем они разделены

| файл | что делает |
|---|---|
| `glue.c` | сорок функций `uacpi_kernel_*`: память, журнал, часы, порты, PCI, замки, отложенная работа |
| `tables.c` | отдать библиотеке таблицы прошивки, не имея права на физическую память |
| `main.c` | подъём и ПРОБА: найти батарею, крышку и адаптер по идентификаторам, спросить их |
| `ec.c` | драйвер встроенного контроллера: обработчик области `EmbeddedControl` |

Разделены по границам ответственности: `glue.c` — наша плата за чужой код, `tables.c` — леса
вокруг недостающего права, `main.c` — то, ради чего всё.

## Собрать

```
nix-build nix -A x86_64.acpi_srv
nix-build nix -A riscv64.acpi_srv
```

Обе архитектуры, `-Wall -Wextra`, без предупреждений. Выходит статический ELF ~310 КиБ.

## Права (позиционно, как во всей системе)

```
service acpi-srv hwprobe:rw fwmem ioport:ec
```

- **0 — `hwprobe:rw`**: таблицы прошивки (`SYS_ACPI_TABLE`), порты, конфигурация PCI. Именно
  `:rw`, не голый токен: тот даёт только чтение, а интерпретатору надо ПИСАТЬ — в командный
  порт прошивки (переход в режим ACPI) и в регистры контроллера;
- **1 — `fwmem`**: отображать физическую память, кроме обычной (`SYS_FW_MAP`);
- **2 — `ioport:ec`**: узкое право на порты встроенного контроллера, если прошивка их объявила.

**Необязательное — последним.** Машина без ECDT права `ioport:ec` не получит вовсе, и стой оно
в середине — сдвинуло бы всё, что правее: программа спросила бы `fwmem` по его номеру и не
нашла. Ровно это и случилось при первом прогоне.

## Что уже работает (проверено в QEMU 15.11.2026)

```
[acpi] таблицы собраны: FADT, DSDT 8 КиБ, всего в XSDT 4
[acpi] starting uACPI, version 7.0.0
[acpi] FACS 0x000000004FFE0000 00000040
[acpi] successfully loaded 1 AML blob, 1710 ops in 19ms
[acpi] namespace initialization done in 7ms: 38 devices, 0 thermal zones
[acpi] прошивка спросила про Windows (код совместимости 0)
[acpi] батареи, крышки и адаптера эта машина не объявляет
```

Последняя строка — не неудача, а правильный ответ: у q35 в QEMU ни батареи, ни крышки нет.
Важно другое — **AML исполняется**: таблицы сняты у ядра, пространство имён построено,
`_INI`/`_STA`/`_REG` выполнены, поиск по идентификаторам отработал.

## Чего ещё НЕТ — названо вслух, а не спрятано

1. ~~Отображение физической памяти~~ — **СДЕЛАНО** (право `fwmem`, `SYS_FW_MAP`). Правило
   оказалось не тем, с которого начинали: «только области, объявленные прошивкой» не работает
   ни на одной настоящей машине — байт-код адресует и окна регистров, которых в карте памяти
   нет вовсе (HPET `0xfed00000`). Осталось одно условие: **никогда не обычная память**, то есть
   ни память процессов, ни образ ядра. Подробно — в `SYS_FW_MAP`.
2. **Прерывание SCI.** Через него приходят события: крышка, кнопка сна, сообщения контроллера.
   `SYS_IRQ_WAIT` у нас есть, не хватает выдачи IRQ-права по вектору из FADT.
3. ~~Обработчик области `EmbeddedControl`~~ — **СДЕЛАН** (`ec.c`, Веха 237): порты из ECDT,
   рукопожатие по битам статуса, чтение и запись. Нет только **очереди запросов `_Qxx`**: о
   том, что контроллеру есть что сказать, узнаёшь по прерыванию SCI, а его пока нет.
4. ~~Доставка в образ~~ — **СДЕЛАНО**: описание C-программ обобщено
   (`Code/programs/c-binaries.list`, короткая запись = программа со своей деривацией), выкладка
   идёт в `Code/programs/prebuilt/<арх>/`, ядро несёт программу семенем.

Остался пункт 2 — события. Без него прошивку можно СПРОСИТЬ (заряд, крышка, адаптер), но она
не может позвать сама: закрытая крышка и смена питания останутся незамеченными.

# Права (capability)

## Почему так

В системе нет ни пользователей, ни root — значит нет и вопроса «от чьего имени
это выполняется». Право принадлежит ПРОЦЕССУ и называет конкретную вещь: вот
этот сервер, вот этот кусок памяти устройства, вот этот store с правом записи.

Что это даёт на практике:

- программа не может попросить больше, чем ей дали при запуске. Не у кого
  просить;
- что именно ей можно — написано ОДНОЙ строкой конфига, и её видно целиком;
- отобрать право можно у работающей программы (диспетчер задач это умеет), и
  она это переживёт.

Раздаёт права тот, кто запускает: конфиг поколения — службам и оболочке,
оболочка — тому, что запускает сама. Сверх выданного взять неоткуда.

## Что пишется в строке запуска

| токен | что даёт |
|---|---|
| `store:r` `store:rw` `store:rwx` | store: читать, писать, исполнять |
| `dev:net:rw` | сырые кадры сети (ими пользуется `net-srv`) |
| `dev:block:rw` | блочное устройство |
| `netdev` | БЫТЬ сетевой картой системы (драйверу) |
| `mmio:ИМЯ` | окно регистров устройства |
| `dma` | память, по которой устройство ходит само |
| `endpoint:ИМЯ` | канал к названной службе |
| `power` | выключить машину |
| `sysview` | видеть процессы и их права |
| `hwprobe` | прочитать регистр устройства (отладка) |
| `env` | получить окружение (не право, а настройка) |
| `arg:ЧТО` | аргумент программе (не право) |

Буквы прав: `r` читать, `w` писать, `x` исполнять, `s` послать сообщение,
`g` передать право дальше. Последняя важна: без `g` держатель пользуется
правом сам, но отдать его не может.

## Пометка «не наследуется»

Восклицательный знак в конце (`mmio:fb!`, `power:wg!`) значит: право выдаётся
процессу как обычно, но его детям не достаётся.

Нужно это держателю-раздатчику. Композитор владеет экраном и выключением — но
если бы они текли по наследству, их получало бы каждое открытое окно. С
пометкой право остаётся у него, а отдаёт он его названным в конфиге поимённо:

```
desktop("power", "bin/vvsh")     шеллу терминала можно выключать машину
desktop("net", "taskmgr")        диспетчеру задач — ходить в сеть
```

Кто просит, система спрашивает у ЯДРА, а не у просителя: имя процесса равно
имени программы в store, из которой он загружен. Назваться чужим нельзя.

## Как посмотреть, что у кого есть

Диспетчер задач (`taskmgr`) показывает процессы и их права, если ему выдано
`sysview`. Он же умеет право ОТОЗВАТЬ у работающей программы — например,
выключить сеть одной из них.

## Чего нет и не будет

- прав у файлов (uid/gid/mode): доступ раздаётся capability, подчиняться
  `chmod` нечему;
- повышения прав (`sudo`, setuid): некуда повышать;
- ambient-доступа: программа не видит ничего, на что ей не дали дескриптор.
  Даже список процессов — под правом.

# soak-smp.txt — ДЛИННЫЙ отстой многоядерности (Веха 170, этап 5).
#
# Короткие прогоны ловят падения. Этот ищет другое — ДРЕЙФ: то, что за минуту не видно, а за
# десять минут выходит наружу. Восемь одинаковых кругов, и после каждого снимок: ряд из восьми
# кадров отвечает на вопрос, растёт ли что-нибудь. Последним кадром — диспетчер задач с точными
# числами памяти и процессов.
#
# Круг: четыре окна открыть → нити (общее адресное пространство на разных ядрах) → счётная
# нагрузка в соседнем окне → мышь и обзор столов, пока идёт счёт → ввод ПОД нагрузкой (проверка
# того, что нажатие, подобранное прикладным ядром, доходит) → четыре окна закрыть.
#
# Как гонять (образ — КОПИЯ рабочего, не он сам):
#   cp Code/target/void.img Code/target/void-soak.img
#   VOID_QEMU_SMP=4 VOID_QEMU_ACCEL=kvm VOID_QEMU_CPU=host \
#     Code/tools/run.sh --img Code/target/void-soak.img --script Code/tools/soak-smp.txt вых/
#
# Что считать нормой (четыре ядра, KVM): память НЕ РАСТЁТ от круга к кругу — на восьми кругах
# столько же, сколько на шестнадцати (полка, а не течь); замеры давали 60–68 МиБ и 10–11
# процессов в зависимости от поколения, поэтому важно именно постоянство, а не само число.
# В консоли ни `[PANIC]`, ни `FATAL TRAP`, ни «ядра молчат о сбросе TLB».

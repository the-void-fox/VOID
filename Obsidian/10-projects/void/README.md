# VOID

> Микроядро на Rust/RISC-V, в основе которого — персистентное, контент-адресуемое,
> capability-защищённое пространство объектов. Ядро для операционных систем, а не клон Linux.

## Тезис
Все современные ОС — амнезики: при потере питания забывают всё в RAM, и поверх этого
факта выстроена башня костылей (файлы, сериализация, БД, save-системы, образы контейнеров,
само понятие «установка»). NixOS, Docker, снапшоты — заплатки над тем, что у ОС нет родного
понятия долговечного воспроизводимого состояния.

VOID берёт линию персистентных capability-систем (KeyKOS / EROS / Grasshopper) и оживляет её
тремя ингредиентами, которых в 90-х не было и которые чинят ровно те причины, по которым она
проиграла:
- **безопасность языка** (Rust) — изоляция без 30 лет CVE на ручной памяти;
- **контент-адресация + неизменяемость** (как Nix/git) — делает персистентность *безопасной
  и воспроизводимой*: откат бесплатен, «испорченного состояния» структурно не бывает;
- **async** — единое IO-тяжёлое пространство объектов быстрое и конкурентное с первого дня.

Центральный примитив — **объект**: неизменяемые значения адресуются по хэшу, изменяемые
«ячейки» ссылаются на значения через capability, всё живёт в персистентном single-level store.

## Стек
- Язык: **Rust** (`#![no_std]`).
- Платформа: **RISC-V** (`riscv64gc-unknown-none-elf`), QEMU `virt`, OpenSBI → S-mode ядро → U-mode userspace; с Вехи 24 арх-специфика — за контрактом `arch/`, второй таргет — **x86_64** (`x86_64-unknown-none`, QEMU `q35`, PVH direct boot, ring3 + `int 0x80`, virtio-pci + MSI-X) — с Вехи 27 полный паритет, включая персистентность; **один диск обслуживает обе архитектуры**.
- Архитектура: **микроядро** + userspace-серверы. Слои совместимости (Linux/POSIX) — отдельные серверы поверх, не в ядре.
- Сборка: Cargo workspace. Окружение: `shell.nix` (Rust+target+QEMU+gdb).

## Код
- Путь: `../Code` (Cargo workspace)
- Точка входа: `Code/kernel/src/main.rs` → `kmain`
- Запуск: `nix-shell` → `cd Code && cargo run`

## Статус
**Фазы 0–3 закрыты (Вехи 1–22); Фаза 4 идёт (Вехи 23–73 закрыты).** Тезис ADR 0002 полон,
система самостоятельна: живой shell `vsh` с вводом ([[interactive-shell]]); capability
передаются по IPC и переживают перезагрузку вместе с c-space ([[ipc-cap-transfer]]); у
процессов ленивая куча и честные page fault ([[process-heap]]). С Вехи 23 **весь userspace —
ELF-объекты store** под корнями `bin/<имя>`, исполняемые по content-id; обновление системы =
смена корня по хэшу ([[elf-userspace]]). С Вехи 24 арх-специфика — за узким контрактом
`arch/`: ядро собирается под **riscv64 и x86_64** из одного дерева ([[arch-boundary]],
[[0005-multiarch-arch-boundary]]); x86_64-дорожка закрыта Вехами 25–27: PVH boot + PML4
W^X + LAPIC ([[x86-bringup]]), полный userspace ring3 + `int 0x80` с арх-корнями
`bin/<arch>/<имя>` ([[x86-userspace]]), virtio-pci + MSI-X + IOAPIC ([[x86-devices]]) —
**полный демо-паритет, и один диск несёт store обеих архитектур** (riscv и x86 читают
файлы друг друга). Веха 28 — микробенчи и память против Linux-гостя в том же QEMU
(цифры — в корневом README репозитория). Веха 29 открыла пакетную дорожку
([[0004-void-pkg]]): store вынесен в `libs/void-store`, хост-мост `void-store-import`
кладёт файлы и NAR (`nix-store --dump`) прямо в образ диска ([[store-bridge]]);
форк rust — сабмодуль `vendor/rust` под std-порт. Веха 30 — контракт запуска процесса
(ABI v2): argv/env и стартовые capability наследуются при exec ([[process-contract]]),
посикс-персоналия выросла на seek/rename. Веха 31 — порт std: таргеты
`*-unknown-void` в форке rust (`vendor/rust`), обычные Rust-программы собираются
обычным cargo и работают на обеих архитектурах ([[std-port]]). Веха 32 — uutils:
std дорос до std::fs (IPC к posixfs) и настоящего аллокатора, ядро — до FP-контекста;
multicall coreutils (форк-сабмодуль `vendor/coreutils`) даёт настоящие
`ls/cat/cp/wc/mv/rm/head/echo` в vsh с одного диска на обеих архитектурах —
**первая честная точка самодостаточности** ([[uutils]]). Веха 33 — политика
коммитов ([[group-commit]]): формат store v2 (индекс дельта-цепочкой, миграция
на лету), group commit с синком при простое, уплотнение по порогу мусора —
последний «до железа» пункт из анализа [[commit-policy]] закрыт. Веха 34 —
сеть ([[virtio-net]]): драйвер virtio-net в ядре отдаёт сырые Ethernet-кадры,
а стек ARP/IPv4/ICMP echo живёт в userspace-сервере `net-srv` — `ping` из vsh
на обеих архитектурах (микроядерность: протоколы не в ядре). Веха 35 — потоки
([[threads]]): ядро планирует нити внутри процесса (`SYS_THREAD_SPAWN/JOIN`,
`SYS_FUTEX`, `SYS_SET_TLS`), форк дорос до `std::thread`, futex `Mutex/Condvar`
и нативного `thread_local!` (TLS Variant I/II) — обычный многопоточный Rust
работает на обеих архитектурах (разблокирует sort/rayon/ripgrep). Веха 36 —
nixpkgs-cross ([[nixpkgs-cross]]): C-мир — GNU hello и bzip2 по РЕЦЕПТАМ
nixpkgs (pkgsCross gcc+newlib из кэша + глю `void-libc` ~610 строк + specs)
работают в vsh на обеих архитектурах; ядро x86 доросло до FP/SSE-контекста
процессов (fxsave64-область кадра — зеркало riscv Вехи 32). Веха 37 —
checkpoint процессов ([[checkpoint]], наследие KeyKOS): вычисления переживают
перезагрузку — `SYS_CHECKPOINT`/`SYS_RESTORE` (семантика setjmp: живому 0,
размороженному 1), образ = дерево объектов store (страницы — дети манифеста,
дедуп и GC бесплатно), vsh `thaw` продолжает замороженный процесс после
ребута с тем же стеком и кучей. Веха 38 — linux-abi ([[linux-abi]], бэкенд B
[[0004-void-pkg]]): неизменённые **static-PIE musl**-бинари из кэша nixpkgs
(hello, busybox) работают под персоналией Linux — транслятор Linux-syscall'ов
в ядре (путь linuxulator), без единой новой инструкции (riscv `ecall` общий,
x86 `syscall` ловится как #UD), стартовый стек с auxv, `brk`/`mmap` поверх
ленивой кучи; обе архитектуры. Веха 39 — wasi ([[wasi]], бэкенд C): неизменённые
**wasm32-wasi**-модули работают через интерпретатор wasmi — тот же .wasm на обеих
архитектурах; раннер `bin/wasirun` — ОБЫЧНАЯ userspace-программа поверх порта std
(ядро не тронуто), WASI-импорты замкнуты на std (fd_write→SYS_WRITE, proc_exit→
SYS_EXIT). **Все три бэкенда ADR 0004 закрыты** — native/nix-cross · linux-abi · wasi.
Веха 40 — декларативный init ([[declarative-init]], первая «фишка NixOS поверх
родного фундамента»): система поднимается по КОНФИГУ-объекту из store, а не по
зашитому сценарию — `service`/`shell` + права-токены (`store:rw`, `endpoint:posixfs`),
init минтит их в домены; поколения = история корня, откат = смена `system/current`
(vsh `switch` + ребут: gen1 полное / gen2 без сети). Модель NixOS честно: язык Nix
вычисляет конфиг на ХОСТЕ (`nix/system.nix` → `nix eval` → мост), VOID грузит результат.
Веха 41 — платформа ([[platform]], слой «платформа» из [[0005-multiarch-arch-boundary]]):
первый шаг с QEMU на РЕАЛЬНОЕ x86-железо — ядро грузится настоящей прошивкой
(multiboot2/GRUB, не только QEMU-PVH), рисует на VGA-экране с **кириллицей** (шрифт CP866 в
знакогенераторе), берёт размер RAM из карты памяти загрузчика, а Веха 42 — драйвер
**PS/2-клавиатуры** (контроллер 8042, скан-коды → ASCII, IRQ1 через IOAPIC): `vsh>`
интерактивен на реальной машине. Проверено на **ASUS X54C** (и в QEMU через GRUB),
загрузочный USB — `Code/boot/mkboot.sh`. Веха 43 — полировка TTY/vsh ([[tty]]): единый
ANSI-механизм (цвета/`clear` толкует и терминал, и VGA-ядро), аппаратный курсор двигается
за письмом, цветной табличный `help`. Веха 44 — папки в posixfs ([[folders]], первый
пункт [[known-gaps]]): у персоналии появились каталоги, пути и `cwd` — `cd`/`pwd`/`mkdir`/`rm`,
вложенность, персистентно — БЕЗ единой правки ядра (файл — корень `f<путь>`, каталог —
индекс-корень `d<путь>`). Веха 45 — редактор строки в vsh ([[tty]]): курсор, вставка/удаление
в позиции, `←`/`→`/`Home`/`End`, история `↑`/`↓` (единый ANSI для PS/2 и serial). Веха 46 —
освобождение фреймов ([[frame-freeing]]): страницы, таблицы и корень завершившейся группы
возвращаются в список свободных и переиспользуются — память больше не течёт (пик при повторных
запусках не растёт). Веха 47 — драйвер **AHCI** ([[ahci]], первый «настоящий» драйвер железа):
store читает/пишет на реальный SATA-диск (проверено — запись пережила ребут), носитель
диспетчеризуется AHCI→virtio-blk; на riscv/QEMU AHCI нет — откат на virtio. Открытый техдолг
и недоделки — [[known-gaps]]. План пакетов — [[void-pkg]].

→ драйвер AHCI/SATA (готово) → **порт неизменённых Linux-драйверов** (dde_linux-стиль, Вехи 55–69):
Lx_kit-рантайм + driver-model + PCI + **сам e1000 компилируется/линкуется/исполняется** ([[lx-e1000-port]])
+ **портированный e1000 читает НАСТОЯЩИЙ QEMU-e1000 через MMIO-cap** ([[lx-e1000-hw]]: MAC/STATUS с реального
железа, x86) + **передаёт кадр по DMA** ([[lx-e1000-tx]]: vendored TX-кольцо на DMA-cap, DD-бит) + **ARP round-trip**
([[lx-e1000-rx]]: RX-кольцо на DMA, TX ARP-запрос → RX ARP-ответ шлюза — двунаправленный трафик). Дальше:
IRQ + мост к net-srv → `ping` через портированный драйвер, затем Atheros/EHCI/wifi X54C тем же
конвейером, и USB-стек.

## ADR
Архитектурные решения в `adr/`. Ключевые:
- [[0001-rust-riscv-microkernel]] — язык, платформа, тип ядра, железная изоляция на старте.
- [[0002-persistent-content-addressed-capability-core]] — стержневой тезис и почему он чинит провал KeyKOS.
- [[0003-phase-3-exec-by-hash]] — Фаза 3: программа как контент-адресуемый объект, exec по хэшу.
- [[0004-void-pkg]] — Фаза 4: пакеты и самодостаточность — резолвер void-pkg (native/nix-cross → linux-abi → wasi) над одним store.
- [[0005-multiarch-arch-boundary]] — мультиархитектурность: узкий контракт `arch/` + cargo-таргеты, без трейтов.
- [[0006-vvsh-lisp-config-shell]] — **vvsh**: маленький Lisp VOID для конфига И шелла, вычисляемый на VOID (самохостинг конфига, шелл-REPL без bash); гомоиконный, Тьюринг-полный намеренно.
- [[0007-graphics-native-compositor]] — **графика**: свой композитор/тулкит на capability-объектах (окно = буфер-объект + cap), софт-рендер → AMD-GPU потом, плавающие → тайлинг «как niri», **персистентный GUI** (окна переживают ребут). Не порт Wayland/DRM/Mesa.

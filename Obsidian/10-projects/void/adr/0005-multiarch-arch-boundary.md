# 0005. Мультиархитектурность: узкий контракт `arch/` и cargo-таргеты

## Контекст
Фаза 4 ([[0004-void-pkg]]) обещает VOID на двух архитектурах — riscv64 (живая) и x86_64
(целевая для реального железа) — из ОДНОГО дерева исходников. До Вехи 24 арх-специфика
(CSR, SBI, PLIC, Sv39, trap-кадр с именами регистров a0…a7, `satp`, `sfence.vma`, `wfi`)
была размазана по модулям ядра: `proc` индексировал регистры кадра числами, `sched` дёргал
CSR, `main` знал про PLIC и UART. Порт в таком виде = переписывание всего.

## Решение
**Граница на этапе компиляции**: модуль `kernel/src/arch/` с узким документированным
контрактом; реализация выбирается по `target_arch` (`#[path]`-cfg), сборка —
`cargo build --target …` (один проект, N образов). Свойства:

- **Никаких трейтов и динамики.** Реализация арха в сборке ровно одна — диспетчеризовать
  нечего; всё обычные функции/типы, инлайнятся как раньше.
- **Опорные типы непрозрачны**: [`TrapFrame`] отдаёт `syscall_num()/arg(i)/set_ret*/advance()/
  new_user()` — какие регистры это значат, знает только арх; `Context` собирается
  конструкторами (`EMPTY/new_task/new_kernel`), поля скрыты.
- **Смысл вместо номеров через границу**: арх сам классифицирует trap из U-mode в enum
  `UserTrap` (Syscall / PageFault{va, kind} / TimerTick / Unknown) — в `proc` не осталось ни
  scause, ни кодов исключений.
- **Политики, а не биты**: маски прерываний сессий — именованные функции
  (`irq_mask_preempt` — «таймер вкл, устройства выкл», `irq_mask_stdin` — наоборот);
  биты STIE/SEIE не покидают арх.
- **Токены пространств**: `space_token(root)`/`space_root(token)` — на RISC-V это satp,
  на x86 будет cr3; `map`/`translate`/`flush_tlb` + флаги `MAP_R/W/X/U` в кодировке арха.
- **Скрипт линковки на арх** (`linker.ld` / `linker-x86_64.ld`) выбирает build.rs по
  `CARGO_CFG_TARGET_ARCH`; для x86 форсирован `relocation-model=static` (таргет по умолчанию
  собирает PIE).
- **Заглушка обязана собираться чисто**: x86_64 сегодня — COM1-вывод и примитивы
  прерываний (настоящие) + `unimplemented!` на всём остальном; ноль предупреждений на обоих
  таргетах — норма. «Обязательства» будущего обработчика trap'ов (какие хуки общего кода
  звать) перечислены кодом в `trap_dispatch_obligations` — это и документация точек
  сращивания, и защита общего кода от dead-code-анализа при сборке заглушки.

Bring-up x86_64 (Вехи 25+: Limine → GDT/IDT → PML4 → LAPIC → syscall → virtio-pci) — это
наполнение заглушки функция за функцией; общий код и контракт при этом НЕ меняются.

## Последствия
- Плюсы: порт = реализация ~30 функций и 2 типов, а не переписывание ядра; вся арх-специфика
  greppable в одном каталоге; `proc`/`elf`/`sched`/`timer` читаются в терминах смысла
  (аргумент syscall'а, «таймер вкл»), не регистров.
- Компромиссы: платформенные константы (RAM/MMIO QEMU virt) пока остаются в общих
  `frame`/`virtio_blk` — их отделит слой «платформа», когда появится второе железо
  (реальный x86 отличается от QEMU virt сильнее, чем x86 от riscv в QEMU); сеяные программы
  пока riscv-only — арх-измерение корней `bin/<arch>/` придёт с рабочим x86-userspace.
- Цена заглушки: поддерживать её компилируемость при росте контракта (окупается — это
  и есть проверка, что новая функциональность не протаскивает арх-специфику мимо границы).

## Альтернативы
- **Трейт `Arch` + generics/dyn:** отвергнуто — реализация на сборку одна, абстракция без
  второго потребителя в рантайме; плата (обвязка, воронка типов) без выгоды.
- **Отдельные крейты на арх:** отвергнуто — версии/фичи/циклы зависимостей (`arch` зовёт
  `proc::handle_user_trap`, общий код зовёт `arch::*`) при нулевой пользе: cfg-модуль даёт
  ту же изоляцию.
- **`#[cfg(target_arch)]` россыпью по коду:** отвергнуто — это и была болезнь, которую лечим:
  граница нигде не зафиксирована и расползается.

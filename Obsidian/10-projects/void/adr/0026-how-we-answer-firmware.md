# 0026. Как VOID представляется прошивке

> Позиция владельца **15.11.2026**, своими словами: если ноутбук отдаёт данные «только
> Windows» — пусть наша система для него и будет этой Windows. Механизмы защиты со сверкой
> ключей не ломаем, это незаконно; речь о базовой комплектации.

## Контекст

### Что такое `_OSI` и почему это не обман

`_OSI` — **опубликованный метод ACPI**, которым ПРОШИВКА спрашивает операционную систему:
«ты поддерживаешь то-то?». Строки вроде `"Windows 2009"` описаны в спецификации ACPI и в
документации Microsoft; вопрос задаёт прошивка, отвечает система. Это интерфейс, а не замок:
здесь нет ни ключей, ни подписей, ни счётчиков, ни чего-либо, что можно было бы обойти.

Так отвечают все. Linux, FreeBSD, Haiku, Managarm говорят «да» на строки Windows, потому что
прошивки проверены только против Windows. Больше того: **сам Linux отвечает «НЕТ» на
`_OSI("Linux")`** (с 2.6.23) — производители использовали эту строку как попало, и ответ «да»
чаще ломал, чем помогал.

### Что из этого правда на X54C — измерено по разобранной прошивке

- Прошивка спрашивает **восемь** строк: `Windows 2001`, `2001 SP1`, `2001 SP2`, `2001.1`,
  `2006`, `2009`, `2012` и `Linux`.
- Ответ кладётся в флаг `OSFG`, и по нему прошивка **ветвится 19 раз**.
- На ветке «Linux» (`OSEG`) яркость уходит в SMI-мейлбокс вместо методов графики.
- Есть устройство **`ATKD`** с `_HID = "pnp0c14"` — это ACPI-WMI, вендорский интерфейс ASUS
  (горячие клавиши, подсветка, индикаторы). На него завязаны **85** мест в таблице.
- У `ATKD` есть метод **`OSVR(x)`**, который пишет `OSFG` НАПРЯМУЮ: прошивка прямо
  предусматривает, что система назовёт себя сама, минуя `_OSI`.

### Главное: названная версия — это ОБЯЗАТЕЛЬСТВО, а не пароль

Самая важная находка. Метод установки яркости выглядит так:

```asl
Method (_BCM, 1) {
    If ((\MSOS () < \OSW8)) {       // Windows 7 и старше
        Local0 = GCBL (Arg0)
        \_SB.LBTN = ((0x0B - 0x01) - Local0)
        \_SB.PCI0.SBRG.EC0.STBR ()  // прошивка САМА крутит подсветку через EC
    } Else { }                      // Windows 8+ — ПУСТО
}
```

Сказав «я Windows 8», мы говорим прошивке: «подсветку беру на себя». Она послушно перестаёт её
трогать. Если бы мы при этом не умели управлять яркостью — экран остался бы с той яркостью, что
была, и причину искали бы неделю.

Нам повезло: яркостью мы управляем сами с Вехи 232 (`BLC_PWM_CTL`, команда `brightness`, см.
[[intel-display]]). То есть обязательство выполнимо — но его надо было УВИДЕТЬ, прежде чем
отвечать.

## Решение

1. **Отвечаем «да» на строки Windows — вплоть до той версии, чьё поведение мы готовы
   обеспечить.** На X54C это `Windows 2012` (Windows 8): подсветку мы умеем. Не «самая новая,
   какую знаем», а «самая новая, за которую отвечаем».
2. **На `_OSI("Linux")` отвечаем «нет»** — по той же причине, по которой это делает сам Linux.
3. **Обязанности перед прошивкой выполняем полностью.** `_OSI` — только одна из них. Туда же
   `_REV`, `_REG` (без него EC молчит — см. [[0025-aml-foreign-interpreter|ADR 0025]]), `_INI`,
   инициализация вендорского устройства (`ATKD.INIT` поднимает флаг `ATKP`, без которого 85
   мест в таблице не работают). Это не притворство, а соблюдение протокола: прошивка ждёт этих
   действий от любой ОС.
4. **Ответ настраивается строкой конфига поколения.** У длинного хвоста найдутся машины, где
   нужный ответ другой; у Linux для этого есть `acpi_osi=`, и у нас будет своё. Настройка в
   конфиге, а не ключом ядра, — по общему правилу ([[0017-settings-from-config]]).
5. **Кем представились — ПЕЧАТАЕМ в журнал.** Ответ меняет поведение машины, значит это
   переменная при разборе неполадок. Молчаливое «я Windows 8» — тот самый молчаливый выбор,
   которого в системе быть не должно ([[void-strictness]]).

### Граница, которую не переходим

Мы разговариваем **с прошивкой на её собственном опубликованном языке**. Мы не подделываем
подписи, не обходим проверки ключей, не выдаём себя за Windows перед чужими драйверами и не
трогаем ничего, что защищено криптографически. Если какая-то машина откроет возможность только
по такой проверке — эта возможность останется закрытой, и мы честно напишем об этом.

Стоит сказать и то, чего ответ «я Windows» **не даёт**: драйверы Windows у нас работать от
этого не начнут. Речь только о том, по какой из своих веток пойдёт прошивка.

## Последствия

- **Яркостью на X54C управляем мы**, прошивка в это не вмешивается. Это уже работает.
- **Горячие клавиши, индикаторы и вендорские события ASUS** идут через `pnp0c14` (ACPI-WMI) и
  требуют, чтобы мы позвали `ATKD.INIT`. Отдельная работа, но дорога названа.
- Появляется **новая переменная при разборе неполадок на чужой машине**: «кем мы
  представились». Поэтому она в журнале.
- Политика одна на все машины, исключения — потом и списком, как у Linux. Начинать со списка
  исключений значит не иметь политики вовсе.

## Альтернативы

- **Отвечать «нет» всем** (самый «честный» вариант). Отброшено по измерению: на X54C прошивка
  уходит на старые ветки, яркость — в SMI, часть путей не та, какую проверяли. Честность,
  которая делает машину хуже, — не честность, а поза.
- **Отвечать «да» самой новой Windows всегда.** Отброшено: это обязательство, которое мы не
  всегда можем выполнить. `_BCM` — живой пример того, как такое обещание гасит функцию.
- **Сразу вести список исключений по машинам.** Это хвост Linux, и он нам пригодится — но
  позже. Сперва внятная политика, потом исключения из неё.

# 0017. Настройки: программа рисует интерфейс по описанию, которое даёт сам конфиг

## Контекст

Конфиг VOID — не файл значений, а **программа** ([[0006-vvsh-lisp-config-shell]]): модули,
условия, списки, `import`, вычисление на самой машине. Настройка системы сегодня — правка
`/etc/system/*.vv` и `rebuild`.

Владелец хочет графические настройки, но не «второй способ настроить систему»: сделать окно,
которое пишет свой формат, значило бы завести вторую правду о конфигурации — ровно то, чего
раскладка поколений и откат ([[declarative-init]]) стараются не допустить.

Предложенная им форма: настройки — **программа, которая спрашивает у конфига «поля на экспорт» и
рисует интерфейс по этой инструкции**, как инспектор Unity, где в панель можно вывести поля и
кнопки.

Форма правильная, но у неё есть острый край: **GUI, редактирующий программу, — это редактор кода
с кнопками**. Он неизбежно испортит то, чего не понял (условие, `append`, вычисленное значение).

## Решение

**Логика остаётся в модулях; графические настройки пишут ТОЛЬКО данные.**

### Объявление поля — рядом со значением

```
# net.vv
on = setting("net.on", true,
             label("Сеть"),
             hint("Выключает сетевой сервис целиком"))
if on { … }
```

`setting(ключ, умолчание, …описание)` делает два дела сразу:

1. **возвращает текущее значение** — из плоского файла данных `/etc/system/values.vv`, если ключ
   там есть, иначе умолчание;
2. **объявляет поле**, когда конфиг вычисляют в РЕЖИМЕ СБОРА (это делает программа настроек).

Два дела в одном вызове — не экономия строк, а защита от расхождения: описание поля физически
не может уехать от места, где значение используется.

- **Тип выводится из умолчания** (`true` → флажок, число → поле/степпер, строка → поле, список →
  список). Отдельного объявления типов нет.
- Ограничения — такими же вызовами: `range(8, 48)`, `choices("Как в Steam", "Русский")`.
- Кнопки — `action("rebuild", "Пересобрать систему")`. **Список действий ЗАКРЫТЫЙ** (`rebuild`,
  `switch`, `pkg update`, `poweroff`): иначе конфиг превращается в способ запустить из GUI что
  угодно — дыра ровно того сорта, который закрывает capability-модель.

### Что пишет программа настроек

Только `/etc/system/values.vv` — плоский список «ключ значение». Ни одной строки логики она не
трогает. Дальше обычный `rebuild`: конфиг перевычисляется, получается поколение, работает откат.
Правки руками и правки из GUI сходятся в одном месте и не спорят.

### Единственная дверь

`setting(...)` — **единственное место, через которое значение приходит извне**. Значение,
вычисленное логикой (`font_px = if hi_dpi { 24 } else { 18 }`), в GUI показывается только для
чтения либо не показывается вовсе: записывать его некуда, и делать вид, что можно, — врать.

## Последствия

- Настройки перестают быть отдельной правдой: это лицо конфига, а не замена ему.
- Плохое значение из GUI не ломает систему молча: `rebuild` перевычисляет конфиг, и при ошибке
  поколение просто не собирается (активное остаётся прежним).
- Механизм общий: **любой** модуль конфига, в том числе конфиг будущей программы, получает
  графические настройки бесплатно — как только объявит поля.
- Вычислителю нужен режим сбора (побочных эффектов у `vvsh-core` нет, так что это дёшево) и
  новый файл данных `values.vv` в раскладке `/etc/system`.
- Настройки, которых нельзя выразить полем (структура сервисов, произвольная логика), остаются
  правкой текста. Это сознательно: конфиг — язык, и GUI не обязан покрывать его целиком.

## Альтернативы

- **GUI правит исходный текст конфига** (surgical rewrite) — работает, пока конфиг прост, и
  разваливается на первом же `if`. Отброшено.
- **Отдельный формат настроек для GUI** — вторая правда о системе, расхождение с конфигом,
  вопрос «кто главный». Отброшено.
- **Схема полей отдельным файлом** — честно, но описание уезжает от значения при первой правке.
  Отброшено в пользу объявления рядом со значением.

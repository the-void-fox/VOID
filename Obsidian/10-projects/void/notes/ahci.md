# Веха 47 — AHCI (SATA): диск на реальном x86

Первый из «настоящих» драйверов железа ([[known-gaps]]). До этого store жил только на
**virtio-blk** — то есть в QEMU/гипервизоре. На реальной машине (ASUS X54C и вообще любой ПК)
диск висит на SATA-контроллере в режиме **AHCI**, и без этого драйвера на металле не было
персистентности вообще (VOID грузился с USB, но писать store было некуда).

Теперь AHCI даёт store'у тот же интерфейс, что virtio-blk (чтение/запись 512-байтных секторов),
поверх AHCI-порта. **Формат диска тот же** — та же `void-disk.img` читается и через virtio (riscv),
и через AHCI (x86): проверено, диск, записанный AHCI в x86-QEMU, читается virtio на riscv.

## Как устроено (полностью в ядре, x86-only)

**Поиск — `arch::probe_ahci()`** (`arch/x86_64/pci.rs`). Скан PCI-шины 0, **всех функций** — это
принципиально: на Intel-PCH SATA-контроллер сидит на **00:1f.2** (функция 2), а обычный
virtio-скан смотрит только функцию 0. Ищем класс **01/06/01** (Mass Storage / SATA / AHCI). У
кандидата: включаем память+bus-master, берём **ABAR** (BAR5), отображаем (`map_mmio`), ставим
**GHC.AE** (AHCI Enable) и ищем порт с диском (**PxSSTS.DET==3**). Возвращаем `(ABAR, порт)`.
Много-контроллерный QEMU (встроенный ich9 без диска на 1f.2 + добавленный с диском) разрулён
проверкой наличия диска в самом порту — пустой контроллер пропускается. Нет AHCI с диском →
`None` → драйвер откатывается на virtio-blk (в QEMU virt/q35 так и происходит). riscv — заглушка
`None` (QEMU virt даёт только virtio-mmio; таргет-riscv использует eMMC/NVMe, не SATA).

**Драйвер — `ahci.rs`.** Ввод-вывод **опросом** (без прерываний) — для первой вехи железного
диска этого достаточно (store читает/пишет синхронно; async-путь остаётся у virtio). Одна команда
за раз под замком, слот 0, одна PRDT-запись на 512 Б.
- **Память** — два обнулённых фрейма ([[frame-freeing|frame]], RAM отображена идентично → физ.
  адрес = вирт., HBA читает их DMA): фрейм A = список команд (0x000, 1 КиБ) + принятый FIS (0x400,
  256 Б) + таблица команд (0x500: CFIS 64 + ACMD 16 + резерв + PRDT); фрейм B = DMA-буфер данных.
  Выравнивания спеки соблюдены естественно (фрейм 4 КиБ-выровнен: CLB 1 КиБ, FIS 256, CTBA 128).
- **Инициализация порта:** остановить (снять ST/FRE, дождаться CR/FR=0), прописать PxCLB/PxFB,
  сбросить PxSERR/PxIS, запустить (FRE, затем ST).
- **Команда:** заполнить шапку слота 0 (CFL=5 dword, W-бит на запись, PRDTL=1) + **Register H2D
  FIS** (тип 0x27, C=1, команда, LBA48, device=0x40 LBA-режим, count=1) + PRDT[0] (адрес буфера,
  DBC=511). Выдать `PxCI бит0=1`, опрашивать до снятия бита или `PxIS.TFES` (ошибка). Проверить
  `PxTFD.ERR`. Команды: **READ DMA EXT (0x25)**, **WRITE DMA EXT (0x35)**, **IDENTIFY (0xEC)**.
- **Ёмкость** — из IDENTIFY (LBA48 в словах 100..103, иначе LBA28 в 60..61).

**Выбор носителя — `object.rs`.** `Disk` (реализация `BlockIo` для store) диспетчеризуется по
атомарному флагу `AHCI_ACTIVE`: `kmain` пробует `ahci::init()` ПЕРВЫМ (так стоит диск на железе),
удался — `object::use_ahci()`, сектора идут через AHCI; иначе — virtio-blk. Store не различает —
сектор 512 Б одинаков.

## Проверка (QEMU q35, диск через `ich9-ahci`, без virtio-blk)

Грузим GRUB-ISO (multiboot2 → `is_real_hardware()`=true → демо пропущены, как на ноуте) с
`void-disk.img` на AHCI:
- `[blk] AHCI SATA: 32768 секторов` — IDENTIFY дал верную ёмкость (16 МиБ/512).
- store **прочитан** через AHCI: 60 объектов, поколение, `system root` с прошлого запуска, vsh
  поднялся со всеми программами (все — из store по AHCI).
- **Запись+персистентность:** `echo … > atest` (сессия 1) → финальный синк 7 КиБ, поколение
  64→65; **ребут** (сессия 2) → `cat atest` вернул текст. Запись дошла до физического диска через
  AHCI и пережила перезагрузку.
- Регрессия: обычный `cargo run` (x86 и riscv) по-прежнему на virtio-blk (probe нашёл встроенный
  AHCI без диска → откат) — 0 изменений.

## Ограничения / осторожно

- **На реальном ноутбуке AHCI пишет в СЫРОЙ SATA-диск** (сектор 0 = суперблок VOID) → **сотрёт
  то, что там есть** (таблицу разделов, существующую ОС). Тестировать только на пустом/запасном
  диске или готовым потерять данные. VOID пока не знает про разделы — весь диск как один store.
- Опрос, а не прерывания; одна команда за раз; только LBA48 READ/WRITE DMA EXT; SATA-диск (не
  ATAPI/CD). BIOS должен быть в режиме **AHCI** (не IDE/legacy) — обычно дефолт.
- Мульти-порт/мульти-диск, NCQ, hot-plug — не реализованы (не нужны store'у).

## Файлы

- `kernel/src/arch/x86_64/pci.rs` — `probe_ahci`/`setup_ahci` (PCI-скан функций, ABAR, порт).
- `kernel/src/arch/riscv64/mod.rs` — `probe_ahci` заглушка (`None`).
- `kernel/src/ahci.rs` — драйвер (init порта, command/read/write, IDENTIFY).
- `kernel/src/object.rs` — `Disk` диспетчер (`AHCI_ACTIVE`/`use_ahci`).
- `kernel/src/main.rs` — выбор носителя на загрузке (AHCI → иначе virtio-blk).

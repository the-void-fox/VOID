# Раскладка WM: что берём из niri владельца

Владелец отдал свой рабочий `~/.config/niri/settings/binds.kdl` как источник умолчаний
(2026-08-09). Это не «список клавиш» — это **модель окон**, и она важнее клавиш.

## Модель: скроллируемый тайлинг колонками

Окна живут в КОЛОНКАХ на бесконечной ленте; фокус ездит между колонками влево-вправо и между
окнами внутри колонки вверх-вниз. Отсюда всё остальное: ширина колонки, «развернуть колонку»,
перенос колонки на другой рабочий стол, вкладки внутри колонки.

**Крестика закрытия НЕ БУДЕТ** (решение владельца): закрывает `Super+Q`. Плавающий режим есть,
но как ИСКЛЮЧЕНИЕ (`Mod+Shift+T`), а не как основа — в отличие от того, что предполагал ADR 0007
(«сперва плавающие»). Наш нынешний композитор (Веха 117) плавающий, и это ступень, а не цель.

## Умолчания, которые переносим

Модификатор `Mod` = Super. Взято дословно, где имеет смысл для нас:

| клавиши | действие |
|---|---|
| `Super+Return` | терминал |
| `Super+Q` | закрыть окно |
| `Super+D` | запуск программы (лаунчер) |
| `Super+Tab` | **обзор окон** (у владельца `toggle-overview`) — быстрый доступ |
| `Super+S` | снимок экрана |
| `Super+H` / `Super+L` | фокус на колонку левее/правее |
| `Super+Up` / `Super+Down` | фокус на окно выше/ниже в колонке |
| `Super+Shift+H` / `Super+Shift+L` | двигать колонку |
| `Super+Shift+Up` / `Super+Shift+Down` | двигать окно в колонке |
| `Super+1`…`Super+9` | рабочий стол |
| `Super+Shift+1`…`9` | перенести колонку на рабочий стол |
| `Super+F` | развернуть колонку |
| `Super+Shift+F` | полный экран |
| `Super+C` | центрировать колонку |
| `Super+Equal` / `Super+Minus` | ширина колонки ±10% |
| `Super+R` | следующая пресет-ширина |
| `Super+Shift+T` | плавающее ⇄ тайловое |
| `Super+Shift+Q` | выйти из сессии → у нас **записать сеанс и выключить** (Веха 151, [[session]]) |
| `Super+Shift+S` | записать сеанс, не выключаясь (нашего сочинения — сохранение, которое видно только выключив машину, нечем отладить) |
| `Super+Z` | раскладка RU/EN (`switch-layout`, Веха 143) |

Не переносим (пока нечему): мониторы (`Mod+Ctrl+*` — у нас один экран), эмодзи, буфер обмена через
noctalia (у нас он будет свой — ADR 0016).

**Мышь с `Super`** — Веха 142 ([[wm-mouse]]); всё это делает КОМПОЗИТОР, окну такие события не
достаются:

| мышь | действие |
|---|---|
| `Super` + ЛКМ, тянуть | переставить окно: горизонталь — колонку, вертикаль — место в колонке |
| `Super` + ПКМ, тянуть | ширина колонки (те же ступени, что `Super+R`) |
| `Super` + колесо | рабочие столы (в обзоре — без `Super`) |
| `Super` + 4-я/5-я кнопка | фокус на колонку левее/правее (ими же приходит наклон колеса) |
| клик в обзоре | по окну — перейти к нему; по пустому месту стола — перейти на этот стол |

## Что из этого следует технически

1. **Клавиш Super и Alt у нас сейчас НЕТ.** Ввод — поток ASCII-байт: `ps2.rs` переводит скан-коды
   в символы и знает только Shift/Ctrl. Оконному менеджеру нужны СОБЫТИЯ (код клавиши + маска
   модификаторов), а не байты. Это предпосылка ко всей раскладке и отдельная работа.
2. **Раскладка живёт в конфиге**, как у терминала с Вехи 100: `bind("wm", "Super+L",
   "focus-column-right")`. Зашитая схема в коде — только запасная.
3. **Снимок экрана** (`Super+S`) в VOID напрашивается сам: кадр — это объект store. «Сделать
   снимок» = положить содержимое экрана объектом и назвать корень; отсюда даром история снимков
   и их дедупликация.
4. **Обзор окон** (`Super+Tab`) — это композитор рисует уменьшенные копии окон. Копии у него уже
   есть (Веха 117: он держит пиксели клиентов), так что это масштабирование, а не новая механика.

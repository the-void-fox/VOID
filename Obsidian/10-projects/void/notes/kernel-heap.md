# Веха 4 — куча ядра

Как в VOID появилась динамическая память. Общий концепт «что такое куча и чем она отличается
от стека» — в справке [[memory-regions]]; здесь — наша конкретная реализация. Связано с
[[sv39-paging]] (арена лежит в отображённой RAM).

## Зачем
До этой вехи ядро могло раздавать только целые 4 КиБ-фреймы ([[sv39-paging|frame]]) и не умело
освобождать. Для объектной модели (Веха 6) и вообще для `Box`/`Vec`/`String` нужна настоящая
куча: выделение произвольного размера + освобождение + переиспользование.

## Из чего собрана
- **frame.rs → `reserve(bytes)`** — выдаёт непрерывный кусок физической RAM под арену кучи
  (двигает тот же bump-указатель, что и `alloc`). Так как в [[sv39-paging]] вся RAM отображена
  идентично (VA == PA), этот физический кусок сразу пригоден как обычная память.
- **sync.rs → `SpinLock<T>`** — взаимное исключение. Нужно, потому что `#[global_allocator]`
  обязан быть `Sync` (это `static`), а значит нужна внутренняя изменяемость под замком.
- **heap.rs → `FreeListAllocator` + `#[global_allocator]`** — сам аллокатор.

## Как работает free-list
Куча — это арена (2 МиБ) и односвязный список её **свободных** блоков.

Хитрость: узел списка не хранится где-то отдельно, а лежит **прямо внутри свободного блока** —
первые байты свободной памяти это его `size` и ссылка `next`. Пока блок свободен, память всё
равно простаивает, вот и держим в ней метаданные. Заняли блок — метаданные затёрлись данными;
освободили — снова записали узел.

- **Выделение (`alloc`)** — *first-fit*: идём по списку, берём первый блок, куда влезает запрос
  (с учётом выравнивания). Если после выделения остался хвост — возвращаем его в список.
- **Освобождение (`dealloc`)** — просто кладём блок обратно в голову списка.

```
арена:  [############ свободно ############]        head → A
alloc 32:[**заня**][###### свободно ######]         head → B(хвост)
free:    [свободно][###### свободно ######]          head → A' → B   (A' снова в списке)
```

## global_allocator и Sync
```rust
#[global_allocator]
static ALLOCATOR: SpinLock<FreeListAllocator> = SpinLock::new(FreeListAllocator::new());
```
`GlobalAlloc` реализован на `SpinLock<FreeListAllocator>`: каждый `alloc`/`dealloc` берёт замок,
работает со списком, отпускает. Замок сейчас не выключает прерывания — это безопасно, пока
обработчики прерываний не аллоцируют (наш таймерный только печатает, а печать памяти не просит).

## Слияние блоков (coalescing) — сделано (доводка после Вехи 9)
Свободный список держится **отсортированным по адресу**. При `dealloc` блок возвращается на своё
место по адресу и **сливается** с примыкающим соседом слева (`prev.end == addr`) и/или справа
(`addr+size == next.start`). Так частые alloc/free не дробят кучу в мелкие несливаемые дырки —
это стало важно с Вехи 9 (async/`Arc`/future аллоцируют и освобождают активно). Фиктивная голова
отличается от реальных блоков по адресу (в неё не сливаем).

## Осознанные упрощения (чиним позже)
- **Дырка перед выровненным началом теряется** (мелкая утечка при экзотических выравниваниях
  больше align узла; для обычных типов старт уже выровнен).
- Арена фиксированного размера (2 МиБ), не растёт.
Апгрейд при нужде: slab/buddy под частые размеры.

## Проверка (вывод в QEMU)
```
[heap] куча ядра готова (2 МиБ, free-list)
[heap] Vec len=16 cap=16: [0, 1, 4, 9, 16, 25] …
[heap] String: "строки на куче — ок"
[heap] Box<[u8;32]> @ 0x802630e0, [0]=0xab
[heap] free+reuse: 0x80263100 → 0x80263100 → тот же адрес ✓
```
Последняя строка — суть: освободили `Box`, следующий такой же `Box` получил **тот же адрес**,
значит свободный список реально переиспользует память.

# Что уже в коробке

**Зачем эта заметка.** Механизм общего кода в VOID есть и работает: пятнадцать модулей
`programs/user/src/*.rs`, подключаемых по пути, семь крейтов в `Code/libs`, тулкит `ui/`. А вот
ОПИСИ не было — и автор новой программы физически не мог узнать, что нужное ему уже написано,
кроме как наткнувшись на него.

Цену этого посчитали 2026-08-19 обходом дублирования. Самый выразительный пример: `obj.rs`
(Веха 139) умеет прочитать объект store целиком — по корню или по content-id, с настоящей длиной,
с блобами по кускам, с отказом вместо паники при нехватке кучи. Его шапка прямо говорит:
«разбирать её каждому потребителю по-своему значит копировать один и тот же десяток строк — с
разными ошибками в каждой копии». Пользовались им трое. Мимо него прошли ещё трое, и каждый
написал свой `read_root` с потолком в 64 или 256 КиБ.

**Правило: прежде чем писать помощник — посмотреть сюда.** Если нужного нет, а потребителей уже
двое — заводить общее (правило «виджеты не писать впрок» требует ДВУХ, а не нуля и не пяти).

## Тулкит интерфейса — `programs/user/src/ui/`

Подключается `#[path = "../ui/mod.rs"] mod ui;`. Три яруса, граница между ними по вопросу
«нужна ли поверхность композитора» ([[void-ui]]).

| модуль | что даёт |
|---|---|
| `paint` | `Rgba`, `Rect`, `Canvas`: пиксели, альфа, скруглённые прямоугольники со сглаживанием. **Годится всем, у кого есть буфер пикселей, включая композитор** |
| `theme` | `Theme` — ЕДИНСТВЕННАЯ палитра системы, из конфига поколения (`ui("accent", …)`). Включая цвета композитора |
| `anim` | `Motion`, `ease_out`, `lerp`, `FRAME_MS` — движение и его кривая, одна на систему |
| `text`, `font` | `Font`: настоящий TTF из пакетов профиля, запасной 8×16, ширина строки |
| `mod` (`Ui`) | виджеты: остров, карточка, кнопка, пилюля, плитка, поле ввода, строка списка, полоса прокрутки, разделители, аватар, кнопка выключения |
| `app` | **цикл**: `Client`, `Scope`, `Input`, `run`, `boot`, `say`. Пачка событий, сон, объём кадра, damage |
| `list` | `List` — фильтрованный список: набранное, выбор, прокрутка, строка под курсором |
| `conf` | активное поколение конфига, право на store, чтение корня |

Чего в тулките нет намеренно: дерева виджетов, раскладочного движка (хватает `Rect::cut_*`),
состояния у виджетов (immediate mode).

## Общие модули userspace — `programs/user/src/*.rs`

Подключаются по пути (`#[path = "../obj.rs"] mod obj;`). Почему модулем, а не частью
`void_user`: здесь нужен `alloc`, а объявить его в библиотеке значило бы потребовать глобальный
аллокатор от ВСЕХ программ, включая живущие без кучи (`hello`, драйверы).

| модуль | что даёт | ловушка, ради которой он есть |
|---|---|---|
| `obj.rs` | **объект store целиком**: корень или content-id, блобы кусками, `try_reserve` | свой `read_root` с зашитым потолком буфера — и файл больше потолка «не читается» |
| `roots.rs` | список корней целиком + разбор по префиксу | частичный список = недосчитаться поколения = **затереть существующее** |
| `profile.rs` | поколения профиля пакетов и их содержимое | |
| `archive.rs` | архивы бинарного кэша nixpkgs: достать и распаковать | |
| `nixname.rs` | разбор имён nix (`<хэш>-<имя>-<версия>`) | |
| `http.rs` | HTTP-клиент, тело потоком прямо в store | |
| `net_cli.rs` | протокол сетевого сервера и обёртка над ним | |
| `net_phy.rs` | мост smoltcp ↔ кадры ядра | |
| `stdio.rs` | соглашение о ЧУЖОМ stdio (размер окна, чтение) | |
| `heap.rs` | куча программы: bump + свободный список | |
| `glyph.rs`, `bitfont.rs` | растровый 8×16 (CP866) для тех, кто рисует текст без терминала | |
| `logo.rs` | знак VOID функциями (без картинки) | |
| `lx_emul.rs` | шим Linux-API для хостинга драйверов | |

## Библиотека syscall'ов — `void_user` (`lib.rs`)

Шимы на все системные вызовы плюс POSIX-персоналия (`sys::posix`). Здесь же:

- **`win`** — протокол окон целиком: операции, события, `Window`, `Layer`, а с Вехи 148.3 и
  `win::sym` — коды клавиш (были расписаны числами в пяти местах). С Вехи 148.4 там же
  **`win::wire`** — РАСКЛАДКА сообщений: `Rd`/`Wr` и по типу на сообщение, `encode` вплотную к
  `decode`. Одно-полевых запросов там нет намеренно: у них нет порядка полей, а значит и нечему
  разойтись;
- с Вехи 150 там же **буфер обмена** (`clip_put`/`clip_id`/`clip_read`) и **`win::modk`** — биты
  модификаторов, стоявшие числами (`mods & 2`) в четырёх местах;
- **`argv`** (Веха 148.5) — аргументы и окружение процесса: `Argv::take()`, `rest()`, `get`/`str`,
  `env_num`/`env_raw`. Ловушка, ради которой он есть: `sys::args` возвращает ПОЛНУЮ длину блоба,
  а кладёт сколько влезло — срез по ней роняет программу, и первым он ронял сам обработчик паники;
- `obj_get_ex` — чтение объекта с НАСТОЯЩЕЙ длиной (без неё «объект ровно с буфер» и «не влез»
  неразличимы);
- `call_ex` — вызов с полным итогом: видно усечение и запроса, и ответа (до Вехи 101 обе усечки
  были невидимы, и так пропала часть сеянного `terminal.vv`).

## Что ещё дублируется (найдено 2026-08-19)

Обход всего дерева нашёл больше, чем успела закрыть Веха 148.3. **Список закрыт целиком**
Вехами 148.4–149 — ниже по одному абзацу на пак.

Закрыто Вехой 149: **прямоугольник композитора**. Он жил кортежами `(i32,i32,i32,i32)` со своими
`intersect`/`union`/`subtract_rect` — при том, что `ui::Rect` рядом и умеет то же самое. Теперь
прямоугольник в композиторе один и типизированный: `damage`, рабочая область, рамка окна,
раскладка ленты, полосы обзора, плитка запуска. Тулкит получил недостающее — `Rect::subtract`
(дополнение до дырки, четыре полосы, без выделения памяти).

Проверка была устроена так, чтобы поймать именно перекос геометрии: один и тот же сценарий (три
окна, смена фокуса, обзор, закрытие) прогнан на сборке ДО и ПОСЛЕ, кадры сравнены попиксельно
ниже панели (часы в панели идут, и их пришлось исключить) — **все совпали**. `wm` вырос на
424 байта, исходник ужался на 40 строк.

Побочно разобрана «полоса мусора в зазоре между окнами» из [[known-gaps]]: поломки нет, в щель
шириной восемь точек видно ОБОИ — знак VOID приходится центром ровно на середину экрана, и его
узкий срез выглядит полосой прокрутки.

Закрыто Вехой 148.3: цикл приложения, объём кадра, палитра, холст композитора, кривая движения,
фильтрованный список, коды клавиш, `say` (было восемь копий, и они разошлись: половина добавляла
перевод строки), стенд QEMU. И один настоящий баг — оборванное чтение файла, у `vvsh` роняющее
шелл паникой, у `ved` тихо отдающее половину файла.

Закрыто Вехой 148.9: **доступ к конфигу PCI**. Семейств аксессоров было три, и различались они
ровно сборкой адреса: `cfg_r32` знала шину 0 и функцию 0 (`dev << 11`), `…f` умела функцию
(`slot << 8`), `…b` — ещё и шину (`bus << 16 | slot << 8`). Это одно и то же число, записанное
трижды. Стало типом `Bdf` с методами (`r32`/`w16`/`bar`/`id`/`class`/`enable`).

Дороже копий обошлись ОБХОДЫ шины: их было четыре, и правило «функции 1..7 существуют только у
многофункционального устройства» каждый нёс по-своему. `dump` читал header type раньше, чем
проверял, отвечает ли функция 0 вообще, а поиск virtio смотрел ТОЛЬКО функцию 0 — устройство на
функции 1 для него не существовало. Ровно ради этого случая и заводилось второе семейство: на
Intel-PCH SATA сидит на 00:1f.2. Теперь обход один (`find`), и функцию видят все.

`pci.rs`: 324 строки → 253 (**−71**), размер ядра тот же (секция `.text` выровнена по 4 КиБ,
правка в неё уложилась). Проверено на живой машине QEMU: опись шины **байт в байт** прежняя,
virtio-blk с MSI-X, virtio-net, virtio-rng, AHCI без диска (обход идёт дальше и находит нужный),
xHCI и e1000 — включая настоящее прерывание INTx у userspace-драйвера `lx_e1000`.

Закрыто Вехой 148.8: **разбор конфига поколения**. Читателей у одного текста было девять, и
каждый нёс свой обход строк: `theme` дважды, `anim`, `wm` трижды, `term`, `pkg`, `ui::conf` —
плюс сам `init` в ядре. Стало крейтом `void-conf` (грамматика + словарь), и крейт этот **общий с
ядром**: модулем в `void_user` ядру его не увидеть, а десятым разбором той же строки платить уже
не за что.

Разошлись копии в трёх местах, и два из них — настоящие ошибки:

1. **граница слова.** `strip_prefix(key)` без проверки следующего знака: при `device nameserver …`
   выше по тексту запрос `name` возвращал `"server 10.0.2.3"`. Проверено живьём — теперь меню
   панели показывает «моя машина», как и написано в конфиге;
2. **хвост.** Значение — одна строка языка, и пробел в ней законен. Половина копий резала хвост
   по пробелам и теряла конец; `term` склеивал его обратно вручную и только для `shell-args`;
3. **словарь.** Список видов был записан ТРИЖДЫ — в ядре (какие строки не ему), в `vvsh-core`
   (сколько у вида полей) и в справке. Новый вид записи требовал правки ЯДРА, иначе система на
   каждой загрузке звала его «неизвестной директивой».

Заодно нашлась и починена помеха ровно этого класса: `term` применяет зашитую схему клавиш
ПОСЛЕ конфига (и только если конфиг не назвал ни одной клавиши), а в той схеме стояли ещё три
строки `terminal …` — и они перебивали конфиг. Система без своих `bind` молча игнорировала
`terminal("font-size", …)`. Проверено: было «кегль 16 вместо 18», стало «вместо 13».

Цена: ядро **на 4 КиБ меньше**, userspace +3.8 КиБ на пять программ; читатели −148 строк, крейт
+300 (из них треть — тесты, гоняются на хосте без QEMU). `profile.rs` из прежнего списка ушёл не
закрытым, а по ошибке учёта: у поколения профиля свой формат со своей версией (`void-profile 1`),
и к конфигу он отношения не имеет.

Закрыто Вехой 148.7: **virtio-транспорт**. Был написан трижды — карты регистров mmio и pci, биты
статуса, структуры колец, `alloc_rings`, `r32`/`w32`/`write_addr` и обе машины рукопожатия.
Стал `kernel/src/virtio.rs`: `Cfg` (сброс → фичи → очередь → DRIVER_OK), `Ring`, `Queue` с
теневыми индексами. Драйверы: 1504 строки → 757 (**вдвое**), всего с общим модулем 1219; ядро
стало на 4 КиБ меньше. Virtio-gpu ([[0018-gpu-ladder]]) теперь начинается с `Cfg::new`, а не с
четвёртой копии.

Копия там уже стоила бага, и он записан прямо в коде: у `virtio_net` в `init_pci` стоял
комментарий «ровно этот шаг делает virtio-blk, и ровно его тут не хватало — сеть поэтому и жила
опросом». Один пропущенный шаг рукопожатия (привязка очереди приёма к вектору MSI-X) — и драйвер
целую веху тихо работал не так, как задумано.

Закрыто Вехой 148.6: **`parse_ipv4`** (было пять копий — `http`, `httpsc`, `vsh`, `vvsh`,
`net-srv`) переехал в `net_cli`, который и так говорит адресом `[u8; 4]`, а **разрешение
спецификации объекта** («64 hex-знака значат content-id, всё прочее — имя корня») стало
`sys::obj_resolve` вместо двух копий в `obj` и `net-srv`. Общий разбор заодно стал СТРОЖЕ:
он считает знаки в октете, и `0000000010.0.2.2` больше не значит `10.0.2.2` — прежние пять
копий такой адрес принимали все пять.

Закрыто Вехой 148.5: **разбор argv и окружения** — `void_user::argv`. Здесь дублирование
оказалось не косметикой, а НАСТОЯЩИМ БАГОМ, и притом прячущим сам себя. `sys::args` возвращает
полную длину блоба, а в буфер кладёт сколько влезло — это записано в его же шапке, и двенадцать
из тринадцати вызывающих на это не смотрели: `argbuf[..n]` при буфере на 128, 256 или 512 байт.
Аргументы длиннее буфера — срез за краем, паника. Тринадцатым был **обработчик паники** (буфер
64 байта): он берёт argv[0], чтобы назвать упавшего, — и падал сам, а паника внутри обработчика
паники прекращает процесс, не напечатав ни строки. Проверено на живой системе: `bin/klog` со ста
сорока знаками аргумента исчезал молча, в журнале ядра пусто, шелл говорил «команда не найдена» —
то же, что о несуществующей программе. Теперь та же команда работает. Заодно поиск переменной
окружения по имени (`STDIO=`, `WM=`, `CAP_*=`, `CWD=`) стал одним местом вместо четырёх. Цена —
+880 байт на восемь программ (+0.1 %).

Закрыто Вехой 148.4: **раскладка сообщений протокола окон**. Теперь она объявлена одним местом —
`win::wire`, где `encode` лежит вплотную к `decode`, а обе стороны зовут их вместо собственных
смещений (ручных `from_le_bytes`/`to_le_bytes` в композиторе было 25, осталось 4 — и те к
протоколу отношения не имеют). Побочно ушла порода отказов: композитор брал поля по индексу, не
глядя на длину, а приёмный буфер у него один на все запросы — короткий запрос дочитывался хвостом
предыдущего, а `OP_CREATE` короче четырёх байт ронял композитор вместе со всем экраном.

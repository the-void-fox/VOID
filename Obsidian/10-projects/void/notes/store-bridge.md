# Веха 29 — мост host→store

Первая веха пакетной дорожки ([[0004-void-pkg]]). Смысл: артефакты попадают в store
**с хоста, без пересборки ядра** — путь «nix build → VOID» становится одной командой.
Это пререквизит std-порта: uutils-бинари (мегабайты) физически не влезут в
include_bytes-семена образа ядра (весь образ сейчас ~450 КиБ).

## Что сделано

### 1. `libs/void-store` — формат store как библиотека

Вся логика `kernel/src/object.rs` (put/get, корни, GC, A/B-коммит, ленивая загрузка)
вынесена в `no_std`-крейт. Носитель абстрагирован минимальным трейтом:

```rust
pub trait BlockIo {
    fn read(&mut self, sector: u64, buf: &mut [u8; SECTOR]) -> bool;
    fn write(&mut self, sector: u64, buf: &[u8; SECTOR]) -> bool;
}
```

- Ядро: `object.rs` — тонкий фасад (SpinLock + `Disk` поверх virtio-blk), публичный
  API модуля не изменился, остальное ядро правок не заметило.
- Хост: `FileIo` поверх `void-disk.img` (seek + read/write_exact).
- **Один формат — одна реализация**: раскладка диска, кадры, roots-blob, A/B-коммит
  живут в одном месте. [[commit-policy|Политика коммитов]] в будущем правится здесь же.
- Синхронизацию библиотека не делает — владелец решает (ядро — замок, хост — эксклюзив).

### 2. `tools/void-store-import` — хост-утилита

Отдельный крейт вне workspace (хостовый таргет; статически под musl через rust-lld,
как bench-linux [[../../30-todo/todo|Вехи 28]] — build-скриптам нужен cc, поэтому
сборка внутри nix-shell). Команды:

```
void-store-import <disk.img> ls                        # корни, поколение, объекты
void-store-import <disk.img> cat <корень>              # содержимое → stdout
void-store-import <disk.img> put <файл> <корень>       # файл → объект + корень
void-store-import <disk.img> nar <архив.nar> <префикс> # NAR → корень на каждый файл
```

Пишет и в чистый образ: первый commit инициализирует store, ядро при загрузке видит
готовые данные и досевает свои программы рядом.

### 3. NAR-распаковщик

NAR — детерминированная сериализация дерева из nix (`nix-store --dump <путь>`).
Формат тривиален: токен = длина(u64 LE) + байты + выравнивание до 8; узлы
regular/symlink/directory. Отображение на store v1 — **плоское**: каждый обычный
файл → объект + корень `<префикс>/<путь>`; исполняемость помечается в выводе (`*`),
симлинки честно пропускаются с предупреждением. Деревья-объекты (каталог как узел
с children) отложены до иерархического posixfs — сейчас им нечем пользоваться.

### 4. Интеграция с posixfs

Импортированные файлы заносятся в индекс каталога (спец-корень `.dir`, формат
`count(1) | [nlen(1) | name]*` — см. [[posix-personality]]), иначе `ls` в vsh их не
покажет (open находит корень и без индекса). Корни `bin/*` — программы, не файлы,
в каталог не заносятся. Пределы posixfs действуют: имя ≤ 32 (длиннее — предупреждение,
файл доступен только по `cat` имени целиком... то есть никак до Вехи 30), файл ≤ 4 КиБ
на чтение через персоналию (объект в store — любого размера, exec читает целиком).

## Проверено вживую

- Круг на чистом образе: put → ls → cat; повторный put того же содержимого → тот же
  content-id (дедуп работает через границу хоста).
- Хост-утилита читает **ядерный** диск (поколение 31, 40 объектов, все корни целы) —
  формат действительно один.
- `nix-store --dump` демо-дерева → `nar` → загрузка **обеих** архитектур с этого же
  диска: `ls` видит импортированное, `cat host.txt` / `cat pkg/demo/*` печатают
  содержимое, посеянное хостом. 0 паник. Ядро надстроило свои коммиты поверх
  хостовых (поколение 33 → 39) — консистентность взаимная.

## Грабли

- **Build-скрипты собираются под хост-триплет**: rustflags musl-таргета на них не
  действуют, `cargo build` вне nix-shell падает «linker cc not found» (blake3 build.rs).
  Лечится сборкой в nix-shell: build-скрипт линкуется динамически nix'овым cc,
  финальный бинарь — статически rust-lld. Та же пара граблей, что у bench-linux.
- `println!` в CLI паникует на `| head` (закрытая труба) — вывод через
  `writeln!(stdout.lock())` с ранним выходом / BrokenPipe = не ошибка.
- Конфиги cargo сливаются вверх по дереву: `tools/*/.cargo/config.toml` перекрывает
  `build.target` из `Code/.cargo/config.toml` (ближний побеждает) — хост-крейты
  обязаны лежать в подкаталоге со своим конфигом и в `exclude` workspace.

## Судьба и следующий шаг

`void-store-import` — эмбрион void-pkg: резолвер вырастет из него, когда появится
второй «вкус» пакета. Рядом лежит форк rust (`vendor/rust`, пин на наш stable
1.97.0, ветка `void`, shallow, llvm-project не инициализирован — LLVM возьмём
внешний из nix) — фундамент Вехи 31 (std-порт). Следующая — **Веха 30: контракт
запуска процесса** (argv/env, стартовые capability конвенцией, exit-коды,
posixfs: seek/rename/unlink/stat) — проверяется нашими же no_std-программами,
Rust-тулчейн не трогает.

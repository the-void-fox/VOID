# Веха 26 — userspace на обеих архитектурах

Продолжение [[x86-bringup]] (Веха 25): x86_64 получил **полный процессный путь** —
ring3, syscall'ы, вытеснение процессов, ленивые кучи, page fault'ы, IPC, exec из store
и **интерактивный vsh**. Демо-паритет с riscv полный, кроме диска (virtio-pci —
Веха 27): store на x86 живёт в RAM, «первый запуск» на каждом боте.

Всё завелось с первого прогона QEMU — грабли Вехи 25 (неопределённый esp) научили
выписывать различия ABI ЗАРАНЕЕ; их набралось пять, все ниже.

## Механика ring3 (`arch/x86_64/`)

- **gdt.rs** — полная GDT: код/данные ring0 (= трамплинные селекторы, перегрузка CS не
  нужна), данные/код ring3 (DPL=3), TSS. `TSS.rsp0` — ядерный trap-стек при прерывании
  из ring3: **аналог sscratch**, выставляется на каждом входе в процесс. Пустая карта
  портов (iomap за лимитом) — IN/OUT из ring3 запрещены.
- **int 0x80 вместо syscall/sysret** — шлюз IDT с DPL=3, вектор 0x80: тот же единый
  TrapFrame, что у всех трапов, ноль нового ассемблера. `syscall/sysret` быстрее, но
  тянет MSR (STAR/LSTAR), swapgs и ручное переключение стека — экономия наносекунд не
  тема bring-up (запишется в bench-веху).
- **enter_user.s** — зеркало riscv-собрата: CR3 + TSS.rsp0 + восстановление 15 GPR из
  кадра + `iretq` (ss/rsp/rflags/cs/rip). Селекторы ring3 и IF=1 форсируются Rust-стороной
  на каждый вход — кадру не позволено их понизить.
- **classify_user** — CS.RPL=3 в кадре → UserTrap: 0x80 → Syscall; #PF → cr2 + биты
  err (1 — Store, 4 — Exec, иначе Load); тик → TimerTick (**EOI до** `handle_user_trap` —
  тот не возвращается, LAPIC остался бы необслуженным навсегда); прочее → Unknown.

## Пять различий ABI, выписанных заранее

1. **`restart()` в контракте TrapFrame**: riscv оставляет sepc на `ecall` — блокирующий
   `SYS_READ` рестартует «бесплатно»; x86 `int` кладёт в кадр адрес СЛЕДУЮЩЕЙ инструкции —
   рестарт требует явного отката `rip -= 2`. Теперь блокировка в SYS_READ зовёт
   `frame.restart()` на обеих архах (riscv — no-op).
2. **Клон адресного пространства — PDPT, не только корень**: на Sv39 user-регион — свой
   слот КОРНЯ, копии корня хватает. На x86 PML4[0] покрывает 0..512 ГиБ — и ядро, и
   user (1..2 ГиБ) под одной записью; разделить её PDPT = процессы перепутают маппинги.
   `clone_kernel_root` копирует PML4 **и** PDPT[0]; PD/PT ядра разделяются.
3. **`hlt` при IF=0 не просыпается от pending** (в отличие от `wfi`!) — `wait_for_interrupt`
   стал идиомом `sti; hlt; cli`: sti действует ПОСЛЕ следующей инструкции, прерывание не
   проскакивает, а обслуживается прямо в окне hlt. Семантика для wait_stdin та же.
4. **rbx запрещён как операнд asm!** (резерв LLVM) — 7-й аргумент syscall'а заезжает в
   rbx через `xchg` и выезжает обратно (нужен только SYS_CALL).
5. **Регистры аргументов ≠ регистры результатов**: rax + rdi,rsi,rdx,r10,r8,r9,rbx против
   a0..a6, результаты rax,rdi,rsi,rdx против a0..a3 — уже разведено контрактом в Вехе 25
   (`set_start_arg`/`set_ret_at`), userspace-шимы получили общий арх-модуль `abi`
   (см. ниже) с этой раскладкой.

## Ввод консоли без IOAPIC — опрос на тиках

Приёмник COM1 опрашивается (`LSR.DR` → кольцевой буфер) в `console_drain`, который
политика таймера и так зовёт **на каждом тике** (паттерн Вехи 20.1: в сессиях процессов
устройства замаскированы, ввод вычерпывается тиками). Маска сессии `stdin` держит таймер
включённым — он и есть часы опроса. Латентность — квант (20 мс), незаметно; честный
IRQ4 через IOAPIC придёт Вехой 27. vsh на x86 интерактивен уже сейчас.

## Один userspace — две архитектуры

- **`programs/user`**: весь асм собран в модуль `abi` (`ecall` / `int 0x80` + noreturn-
  вариант) — 17 шимов стали арх-нейтральными вызовами `abi::syscall(num, a0..a6) →
  (r0..r3)`. `_start(a0, a1)` — обычный `extern "C" fn`: SysV кладёт аргументы в rdi/rsi,
  ровно куда `TrapFrame::new_user`/`set_start_arg` их пишут.
- **kernel/build.rs** собирает программы под архитектуру ядра (`--target` по
  `CARGO_CFG_TARGET_ARCH`); дочерний cargo наследует `Code/.cargo/config.toml` — x86-
  программы получают `relocation-model=static` бесплатно. `linker.ld` программ стал
  арх-нейтральным (убран `OUTPUT_ARCH`, добавлен `.got`).
- **Корни `bin/<arch>/<имя>`** — арх-измерение: сев и exec резолвят через
  `prog_root()`; пользователь и программы говорят `bin/hello`, архитектуру знает ядро.
  Один диск может нести бинари обеих архитектур бок о бок — content-id, естественно,
  разные (`hello`: riscv `32579bfeef…`, x86 `bcbedca368…`). Доарховые корни `bin/<имя>`
  (Вехи 23–25) мигрируются на севе (del_root → байты уходят в GC).

## Проверено

1. Оба таргета собираются с нуля предупреждений (x86 — с первого раза).
2. x86_64, полный прогон: 13 посеяно под `bin/x86_64/*` → все ядерные демо → blk/store/
   cap-ipc демо (отказы прав честные) → **вытеснение ring3: 48 тиков, A/B перемежаются** →
   ленивая куча (4 фолта) + crash убит по #PF вне кучи (ядро живо) → posix/mini-sh →
   exec hello по content-id → **интерактивный vsh**: ls · cat · echo → m25.txt ·
   run bin/hello · exit → GC → commit (RAM) → idle. Паник 0.
3. riscv-регрессия: свежий диск — 13 посеяно под `bin/riscv64/*`, полная vsh-сессия;
   перезагрузка — 13 актуально, `m25.txt` и greeting живы, PANIC/FATAL 0.

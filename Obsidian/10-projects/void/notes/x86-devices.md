# Веха 27 — устройства x86_64: один диск, две архитектуры

Финал x86-дорожки Фазы 4 ([[x86-bringup]] → [[x86-userspace]] → эта веха): диск и
честный консольный IRQ на q35 — **демо-паритет полный**, и главный приз: один
`void-disk.img` несёт персистентный store с программами обеих архитектур. riscv пишет
файл — x86 его читает; x86 пишет — riscv читает; корни `bin/riscv64/*` и `bin/x86_64/*`
живут бок о бок и не мешают друг другу. «NixOS-образ, который грузится на чём угодно» —
в миниатюре и с capability.

## Транспорт virtio — новая ось контракта `arch/`

Драйвер virtio-blk был приросшим к virtio-mmio. Разрез прошёл по спецификации:
virtqueue (desc/avail/used, цепочки, статусная машина ACKNOWLEDGE→DRIVER→FEATURES_OK→
DRIVER_OK) — **общий**, различается только «где регистры и как дёрнуть устройство»:

- контракт: `arch::probe_virtio_blk() -> Option<BlkDevice { transport, irq }>`;
  `BlkTransport::Mmio { base }` (riscv: скан 8 слотов QEMU virt — переехал из драйвера
  в арх) или `BlkTransport::Pci { common, notify_base, notify_mult, isr, device }`;
- драйвер: два пути init (mmio-регистры / поля common_cfg — биты статуса те же),
  в горячем пути транспорт решает лишь `notify_queue0()` и `irq_ack()`.

## PCI ровно на один диск (pci.rs)

Конфиг-порты 0xCF8/0xCFC, шина 0, функция 0 — где q35 и держит `-device
virtio-blk-pci`. BAR'ы уже назначены SeaBIOS: только читаем и отображаем
(`paging::map_mmio` — рантайм-достройка таблиц ядра; обязана успеть до первого клона
пространств — успевает: probe до первого spawn). Адреса структур virtio — из
vendor-capabilities (id 0x09, типы common/notify/isr/device) по спецификации
virtio-pci modern; раннер ставит `disable-legacy=on` (зеркало `force-legacy=false`
на mmio).

## MSI-X вместо INTx — обход болота

Классическая маршрутизация INTx на q35 (PIRQ-свопы чипсета, interrupt line ≠ GSI) —
трясина. **MSI-X** её обходит целиком: запись 0 таблицы устройства = адрес LAPIC
(0xFEE0_0000) + вектор `VEC_BLK` (34); `queue_msix_vector = 0` в common_cfg — и
завершения очереди приходят вектором прямо в CPU, как и задумано на PCIe.
Async-путь ([[async-executor]]) заработал без изменений: `[D] async-чтение сектора 0:
[56 4f 49 44] — разбужен IRQ диска` — future разбужена MSI-X-сообщением, и
`56 4f 49 44` — это «VOID», магия суперблока, записанного riscv-ядром.

## IOAPIC — консоль по прерыванию

GSI4 (COM1) → вектор `VEC_CONSOLE` (33); UART получает IER.DR и OUT2 в MCR (классика:
без OUT2 линия «не воткнута»). Сон до ввода стал честным: `irq_mask_stdin` теперь
маскирует LVT-таймер (как STIE-выкл на riscv) — простой идёт до прерывания консоли,
а не тиков-опроса. Опрос LSR на тиках остался вторым, идемпотентным путём — он
подбирает байты в сессиях процессов.

Прерывания устройств на x86 обрабатываются **из любого кольца**: стаб полностью
сохраняет кадр — короткая работа (drain/on_irq) + EOI + iretq возвращают прерванное
как ни в чём не бывало, хоть ядро, хоть ring3-процесс. Масок сессий для устройств
поэтому не нужно вовсе (riscv-модель с SEIE-масками — следствие его trap-пути,
который из U-mode всегда уходит в планировщик).

## Грабли

- **Пустые шлюзы IDT**: вектора 33/34 маршрутизированы, а гейтов в IDT нет → #GP с
  `err = 0x112`. Чтение: у #GP код ошибки может указывать на IDT — бит 1 (IDT) + индекс
  `0x112 >> 3 = 34`. Ошибка сама называет виновника — если знать, как спросить.
- Первый прогон упал этим #GP **посреди загрузки после commit'ов** — диск пережил без
  единой потери: A/B-индекс поднял состояние следующим ботом. Незапланированный
  crash-тест атомарности store пройден.
- `map_mmio` после `mm_enable` дозаполняет таблицы ядра: новые записи верхних уровней
  не попали бы в уже сделанные клоны пространств — порядок «probe до первого spawn»
  теперь инвариант (задокументирован у map_mmio).

## Проверено (кросс-арх протокол)

1. Оба таргета — ноль предупреждений.
2. **x86 на диске, написанном riscv**: store загружен (поколение 11, system root
   riscv-бота), c-space восстановлен (9 доменов), 13 посеяно под `bin/x86_64/*`
   (riscv-корни не тронуты), async по MSI-X (2 IRQ), vsh: `m25.txt` (riscv) читается,
   `echo hello from x86 > m27.txt`, свой hello по content-id. Паник 0.
3. **x86 перезагрузка**: 13 актуально `bin/x86_64/*`, оба файла живы. Паник 0.
4. **riscv на том же диске**: store от x86-бота (поколение 19), 13 актуально
   `bin/riscv64/*`, `cat m27.txt` → «hello from x86», свой hello, 86 вытеснений,
   exit — чисто. Паник 0.

# vvsh — раскладка конфига: FS-источник, поколение-сборка, bootstrap

Как система конфигурируется на vvsh ([[0006-vvsh-lisp-config-shell]]) на практике. Ключевое
решение: **eval конфига происходит на `rebuild` в поднятой системе, а НЕ на буте.** Это снимает
«курицу-яйцо» (A2: vvsh — userspace-программа, для eval нужен процесс+posixfs) и делает откат
честным.

## Три слоя

1. **Источник (правишь ты)** — модульные `.vv`-файлы в **`/etc/system/`** (posixfs). `default.vv`
   наверху `import`-ит модули (`networking.vv`, `services.vv`, `shell.vv`, `hardware.vv`, …).
   Обычные файловые команды (`ls /etc/system`, `cat`, `mv`, `echo>`; редактор — позже). Это
   аналог `/etc/nixos/` + `imports = [ … ]`.
2. **Сборка (`rebuild`)** — в УЖЕ поднятой системе `vvsh` читает `/etc/system/default.vv`,
   вычисляет → нормализованные данные (тот же формат, что сегодня печатает `nix/system.nix`:
   строки `service NAME cap…` / `shell NAME cap…`) → **коммит новым поколением** `system/gen<N>`,
   двигает `system/current`. Контент-адресация → дедуп/откат бесплатны; поколение = контент-адресный
   КЭШ выхода eval (как деривация Nix: мощный язык → фиксированный результат по хэшу).
3. **Бут (ядро)** — читает уже-нормализованное поколение из корня `system/<gen>` (**как сегодня**,
   `init.rs::apply`), поднимает сервисы. **eval в буте не участвует, зависимости от posixfs на буте
   нет, откат честный** — бутимся всегда с ЗАКОММИЧЕННОГО снимка, а не с живого `/etc` (который мог
   уже уехать под следующую сборку).

```
/etc/system/*.vv   --(vvsh rebuild: eval на VOID)-->   system/gen<N> (норм. данные)
   источник, ты правишь                                    снимок, ядро читает на буте
```

## Почему eval НЕ на буте (обоснование)

- **Курица-яйцо снята.** Конфиг решает, какие сервисы поднять — включая posixfs. Если бы eval шёл
  на буте, а vvsh — userspace-программа, которой для чтения `/etc` нужен posixfs… тупик. Перенос
  eval в `rebuild` (posixfs уже есть, шелл есть) убирает тупик: на буте ядру нечего вычислять.
- **Откат честный.** Старое поколение — это старый нормализованный снимок; `/etc` мог измениться.
  Бут с закоммиченного снимка гарантирует «откатился на gen — получил ровно ту систему».
- **Бут дёшев и аудируем.** Путь загрузки простой (читаем данные), вся мощь языка — на этапе
  сборки. Ровно разделение из ADR: «язык вычисляет → данные; init грузит данные».
- **Самохостинг.** Правишь `.vv` на VOID, `rebuild` на VOID — хостовый Nix для СИСТЕМНОГО конфига
  не нужен (Nix остаётся для ПАКЕТОВ, [[0004-void-pkg]]).

## Модульность (первого класса)

`(import "networking.vv")` возвращает ВКЛАД модуля (список сервисов/настроек), `default.vv` их
СЛИВАЕТ. Это настоящая модульность, не текстовый include. Старт — **простой список-конкат**
(каждый модуль → список записей, `default.vv` конкатенирует); NixOS-подобные options/merge — позже.

## Настройки сервисов (Веха 92)

Сервису можно задать не только права, но и **поведение** — токеном `arg:` ([[declarative-init]]).
Сеть по умолчанию берёт адрес по DHCP; статика прописывается прямо в `networking.vv`:

```lisp
(list (service "net-srv" "dev:net:rw"
               "arg:dhcp=off" "arg:ip=10.0.2.99/24" "arg:gw=10.0.2.2" "arg:dns=10.0.2.3"))
```

Дальше как обычно: `rebuild` → новое поколение → ребут. Проверено сквозняком (Веха 92,
[[net-stack]]): правка файла → `rebuild` → загрузка со статикой, `ping` и `resolve` работают.
Откат — `switch` на прежнее поколение, файл при этом можно не трогать.

## Настройки ПРОГРАММ в том же конфиге (Веха 100)

Терминал настраивается там же, где система, и обычным модулем — `/etc/system/terminal.vv`:

```lisp
(define on #t)                       ; #t — мультиплексор term, #f — текстовый vsh
(append
  (list (shell "term" "endpoint:posixfs" "store:rwx" "mmio:fb" "env"))
  (list (terminal "font-size" 18))
  (list (bind "normal" "C-a" "mode-pane")
        (bind "pane"   "|"   "split-v")))
```

Две новые записи — `(terminal ключ значение)` и `(bind режим клавиша действие)` — нормализуются
в такие же строки, как `service`/`shell`:

```text
shell term endpoint:posixfs store:rwx mmio:fb env
terminal font-size 18
bind normal C-a mode-pane
bind pane | split-v
```

**Один текст, несколько читателей.** Ядро берёт из поколения свои строки (`service`/`shell`) и
молча пропускает чужие; `term` читает АКТИВНОЕ ПОКОЛЕНИЕ из store (`system/current` → имя →
`system/<имя>`) и берёт `terminal`/`bind`. Разделять их на два объекта не за что: конфигурация
системы — одна вещь, у неё одна история поколений и один откат. Кто какие строки берёт — дело
читателя, а не хранилища.

Отсюда же следует, что настройка терминала **проходит через `rebuild`**, а не читается из живого
`/etc`: сломанная правка не уносит работающую систему, откат делает `switch`. Цена — «поправил и
перезагрузился» вместо «поправил», и она осознанная.

Форму записей проверяет СБОРКА: `(bind "pane" "split-v")` (забыли клавишу) — ошибка `rebuild`, а
не тихо пропущенная строка на уже загруженной системе.

Чего в конфиге нет — то у программы своё умолчание: `term` держит схему по умолчанию тем же
текстом и разбирает тем же кодом, поэтому «из конфига» и «из коробки» не могут разъехаться. Если
`bind`-строк нет вовсе — схема целиком умолчательная; если есть хоть одна — схема задаётся
конфигом ЦЕЛИКОМ (слияние означало бы, что клавишу нельзя отвязать).

> **Скобки в примерах — временные.** Поверхностный синтаксис `.vv` будет заменён на инфиксный
> ([[0013-vvsh-surface-syntax]]); меняется только ридер. Трёхслойная раскладка выше при этом не
> двигается — и именно она делает замену дешёвой: в поколениях лежат НОРМАЛИЗОВАННЫЕ данные, а не
> исходник, поэтому старые поколения останутся загружаемыми, а конвертировать придётся лишь
> `/etc/system/*.vv`.

## `switch` без перезагрузки — что для него нужно (разбор 2026-08-04)

Вопрос владельца: сделать как в NixOS — `rebuild switch` применяет конфигурацию НА ЖИВОЙ системе,
без ребута. Ответ: да, но это не одна работа, а четыре, и они очень разной цены.

**Что почти даром — и даёт бо́льшую часть ощущения.**

1. **Перечитать настройки терминала.** `term` уже читает активное поколение из store сам; не
   хватает только команды «перечитай». Ноль изменений в ядре, чистый userspace. Пересобрать
   придётся кэш глифов, поверхность и гриды при смене кегля (`Grid::resize` есть). Это ровно то,
   что правят чаще всего, — клавиши и вид.
2. **Только ДОБАВИТЬ сервис.** Поднять новые `service`-строки, не трогая работающие. Не требует
   ничего из тяжёлого списка ниже.

**Что мешает настоящему switch.**

1. **Завершить чужой процесс нечем.** Ни `SYS_KILL`, ни аналога (последний syscall — 43). Без
   этого нельзя ни убрать сервис, ни перезапустить изменённый. Тот же долг, из-за которого
   закрытая панель мультиплексора оставляет сироту ([[multiplexer]]).
   Половина фундамента уже есть: **отзыв прав на умерший процесс работает** (`cap::revoke_process`,
   Веха 89) — эндпоинты на него становятся `Stale`, и вызов клиента честно ошибается, а не виснет
   навсегда. Недостаёт самого завершения: снять с планировщика, освободить кадры и адресное
   пространство, разбудить ждущих.
2. **Клиент держит право на КОНКРЕТНЫЙ pid.** Перезапустил `posixfs` — у всех его клиентов право
   стало `Stale`, и взять новое НЕГДЕ: службы имён нет, права раздаёт init на старте. Значит
   «перезапустить сервис» сегодня означает «перезапустить и всех, кто им пользуется», то есть
   почти систему. Настоящее лечение — право на ИМЯ службы, а не на pid (реестр эндпоинтов,
   переживающий перезапуск). В NixOS этой задачи нет вовсе: там связь идёт через путь сокета в
   ФС, и имя переживает рестарт само.
3. **Кто вправе переконфигурировать.** Сейчас конфиг применяет ядро на буте (`init::apply`). Для
   switch нужна точка входа в это же — и она обязана быть ПОД ПРАВОМ (свой `cap::Target`, токен
   вроде `system:switch` в конфиге). Иначе «право писать в store» молча становится правом
   переделать машину, а модель как раз про то, что таких неявных прав не бывает.
4. **Шелл сам записан в конфиге.** Активация из шелла — это замена земли, на которой стоишь;
   у switch должен быть особый случай «себя не перезапускаю» (или перезапуск через посредника).

**Порядок, если брать:** (S1) `reload` в терминале → (S2) завершение процесса под capability
+ освобождение ресурсов → (S3) диф поколений и активация в ядре → (S4) имена эндпоинтов, чтобы
перезапуск сервиса не рвал клиентов.

**Оговорка про мотивацию.** VOID персистентен ([[checkpoint]]): состояние переживает
перезагрузку, поэтому «перезагрузиться» здесь дешевле, чем в Linux. Это довод не торопиться с
S3–S4, а не отказываться: S1 всё равно нужен, а S2 закрывает уже записанный долг.

## Команды (в шелле)

- **`rebuild`** — eval `/etc/system/default.vv` → коммит нового поколения → `current`. (Эволюция
  нынешнего `sysdef`: раньше файл клался в корень как есть; теперь ВЫЧИСЛЯЕТСЯ.)
- **`gens`** — показать только поколения `system/*` + какое `current` (снимает боль: `roots` валит
  в кучу `bin/<arch>/*` и `system/*`; `roots` остаётся низкоуровневой отладкой).
- **`switch GEN`** — выбрать поколение (откат; уже есть) → после ребута.

## Вехи

- **M1a** ✅ (Веха 75, [[vvsh-lang]]) — вычислитель есть (`libs/vvsh-core` + `bin/vvsh`); `vvsh eval
  FILE` читает `.vv` из posixfs, вычисляет НА VOID, печатает нормализованный текст. Эквивалентность
  gen1/gen2 — host-тесты байт-в-байт; пайплайн — проверен в QEMU на обеих арх.
- **M1b** ✅ (Веха 76, [[vvsh-lang]]) — `(import "модуль.vv")` через `ModuleLoader` (бинарь — posixfs,
  тесты — карта) + слияние `append`; кэш + детект циклов. В QEMU: `/etc/system/*.vv` → gen1 точно.
- **M1c** ✅ (Веха 77, [[vvsh-lang]]) — `vvsh rebuild` (eval `/etc/system/default.vv` → коммит
  `system/gen<N>` + `current`, dedup), `vvsh init-config` (сев `/etc/system/*.vv`), `vvsh gens`. Бут
  читает снимок (не менялся); шелл получил `store:rwx` (READ для dedup/`gens`, мягкая деградация без
  READ). QEMU (обе арх): правка `net.vv` → rebuild → **ребут грузит gen4** (без сети). **Фаза КОНФИГА
  (M1) закрыта — хостовый Nix для системного конфига не нужен.**

Далее (пруф №2) — vvsh как движок ШЕЛЛА (конвейеры/переменные/функции поверх того же языка).

## Реализация

- **`libs/vvsh-core`** — `no_std`+`alloc` крейт: reader (S-выражения) + `Value` + вычислитель +
  каноничный принтер + `normalize_config`. `#![cfg_attr(not(test), no_std)]` → host-тесты
  (`cargo test`) для парсера/eval без QEMU. Потребитель — `bin/vvsh` (path-dep из `programs/user`);
  ядро крейт НЕ линкует (A2).
- **`programs/user/src/bin/vvsh.rs`** — программа: `eval FILE` (M1a), позже `rebuild`.

# vvsh — раскладка конфига: FS-источник, поколение-сборка, bootstrap

Как система конфигурируется на vvsh ([[0006-vvsh-lisp-config-shell]]) на практике. Ключевое
решение: **eval конфига происходит на `rebuild` в поднятой системе, а НЕ на буте.** Это снимает
«курицу-яйцо» (A2: vvsh — userspace-программа, для eval нужен процесс+posixfs) и делает откат
честным.

## Три слоя

1. **Источник (правишь ты)** — модульные `.vv`-файлы в **`/etc/system/`** (posixfs). `default.vv`
   наверху `import`-ит модули (`networking.vv`, `services.vv`, `shell.vv`, `hardware.vv`, …).
   Обычные файловые команды (`ls /etc/system`, `cat`, `mv`, `echo>`; редактор — позже). Это
   аналог `/etc/nixos/` + `imports = [ … ]`.
2. **Сборка (`rebuild`)** — в УЖЕ поднятой системе `vvsh` читает `/etc/system/default.vv`,
   вычисляет → нормализованные данные (тот же формат, что сегодня печатает `nix/system.nix`:
   строки `service NAME cap…` / `shell NAME cap…`) → **коммит новым поколением** `system/gen<N>`,
   двигает `system/current`. Контент-адресация → дедуп/откат бесплатны; поколение = контент-адресный
   КЭШ выхода eval (как деривация Nix: мощный язык → фиксированный результат по хэшу).
3. **Бут (ядро)** — читает уже-нормализованное поколение из корня `system/<gen>` (**как сегодня**,
   `init.rs::apply`), поднимает сервисы. **eval в буте не участвует, зависимости от posixfs на буте
   нет, откат честный** — бутимся всегда с ЗАКОММИЧЕННОГО снимка, а не с живого `/etc` (который мог
   уже уехать под следующую сборку).

```
/etc/system/*.vv   --(vvsh rebuild: eval на VOID)-->   system/gen<N> (норм. данные)
   источник, ты правишь                                    снимок, ядро читает на буте
```

## Почему eval НЕ на буте (обоснование)

- **Курица-яйцо снята.** Конфиг решает, какие сервисы поднять — включая posixfs. Если бы eval шёл
  на буте, а vvsh — userspace-программа, которой для чтения `/etc` нужен posixfs… тупик. Перенос
  eval в `rebuild` (posixfs уже есть, шелл есть) убирает тупик: на буте ядру нечего вычислять.
- **Откат честный.** Старое поколение — это старый нормализованный снимок; `/etc` мог измениться.
  Бут с закоммиченного снимка гарантирует «откатился на gen — получил ровно ту систему».
- **Бут дёшев и аудируем.** Путь загрузки простой (читаем данные), вся мощь языка — на этапе
  сборки. Ровно разделение из ADR: «язык вычисляет → данные; init грузит данные».
- **Самохостинг.** Правишь `.vv` на VOID, `rebuild` на VOID — хостовый Nix для СИСТЕМНОГО конфига
  не нужен (Nix остаётся для ПАКЕТОВ, [[0004-void-pkg]]).

## Модульность (первого класса)

`(import "networking.vv")` возвращает ВКЛАД модуля (список сервисов/настроек), `default.vv` их
СЛИВАЕТ. Это настоящая модульность, не текстовый include. Старт — **простой список-конкат**
(каждый модуль → список записей, `default.vv` конкатенирует); NixOS-подобные options/merge — позже.

## Настройки сервисов (Веха 92)

Сервису можно задать не только права, но и **поведение** — токеном `arg:` ([[declarative-init]]).
Сеть по умолчанию берёт адрес по DHCP; статика прописывается прямо в `networking.vv`:

```lisp
(list (service "net-srv" "dev:net:rw"
               "arg:dhcp=off" "arg:ip=10.0.2.99/24" "arg:gw=10.0.2.2" "arg:dns=10.0.2.3"))
```

Дальше как обычно: `rebuild` → новое поколение → ребут. Проверено сквозняком (Веха 92,
[[net-stack]]): правка файла → `rebuild` → загрузка со статикой, `ping` и `resolve` работают.
Откат — `switch` на прежнее поколение, файл при этом можно не трогать.

## Команды (в шелле)

- **`rebuild`** — eval `/etc/system/default.vv` → коммит нового поколения → `current`. (Эволюция
  нынешнего `sysdef`: раньше файл клался в корень как есть; теперь ВЫЧИСЛЯЕТСЯ.)
- **`gens`** — показать только поколения `system/*` + какое `current` (снимает боль: `roots` валит
  в кучу `bin/<arch>/*` и `system/*`; `roots` остаётся низкоуровневой отладкой).
- **`switch GEN`** — выбрать поколение (откат; уже есть) → после ребута.

## Вехи

- **M1a** ✅ (Веха 75, [[vvsh-lang]]) — вычислитель есть (`libs/vvsh-core` + `bin/vvsh`); `vvsh eval
  FILE` читает `.vv` из posixfs, вычисляет НА VOID, печатает нормализованный текст. Эквивалентность
  gen1/gen2 — host-тесты байт-в-байт; пайплайн — проверен в QEMU на обеих арх.
- **M1b** ✅ (Веха 76, [[vvsh-lang]]) — `(import "модуль.vv")` через `ModuleLoader` (бинарь — posixfs,
  тесты — карта) + слияние `append`; кэш + детект циклов. В QEMU: `/etc/system/*.vv` → gen1 точно.
- **M1c** ✅ (Веха 77, [[vvsh-lang]]) — `vvsh rebuild` (eval `/etc/system/default.vv` → коммит
  `system/gen<N>` + `current`, dedup), `vvsh init-config` (сев `/etc/system/*.vv`), `vvsh gens`. Бут
  читает снимок (не менялся); шелл получил `store:rwx` (READ для dedup/`gens`, мягкая деградация без
  READ). QEMU (обе арх): правка `net.vv` → rebuild → **ребут грузит gen4** (без сети). **Фаза КОНФИГА
  (M1) закрыта — хостовый Nix для системного конфига не нужен.**

Далее (пруф №2) — vvsh как движок ШЕЛЛА (конвейеры/переменные/функции поверх того же языка).

## Реализация

- **`libs/vvsh-core`** — `no_std`+`alloc` крейт: reader (S-выражения) + `Value` + вычислитель +
  каноничный принтер + `normalize_config`. `#![cfg_attr(not(test), no_std)]` → host-тесты
  (`cargo test`) для парсера/eval без QEMU. Потребитель — `bin/vvsh` (path-dep из `programs/user`);
  ядро крейт НЕ линкует (A2).
- **`programs/user/src/bin/vvsh.rs`** — программа: `eval FILE` (M1a), позже `rebuild`.

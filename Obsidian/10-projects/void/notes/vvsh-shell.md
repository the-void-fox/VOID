# vvsh — фаза ШЕЛЛА: интерактивный REPL (пруф №2)

Вторая половина ADR 0006: vvsh как интерактивный шелл-REPL поверх того же гомоиконного Lisp'а
([[vvsh-lang]]), что и конфиг ([[vvsh-config-layout]]). Один язык для конфига и шелла, без порта bash.

## Принятые решения (обсуждено)

- **vsh остаётся ВСЕГДА — внешний спасательный шелл.** vvsh НЕ заменяет vsh. Модель: vsh = внешний/
  login-шелл (минимальный, надёжный), **vvsh repl = богатый под-шелл**, в который заходишь из vsh
  (`run vvsh repl`) и возвращаешься по выходу/падению. Упадёт vvsh — vsh ловит обратно. Строку `shell`
  в конфиге не трогаем; никакой рискованной замены.
- **Гибридный синтаксис (eshell/rc).** Строка, начинающаяся с `(` — Lisp (`(+ 1 2)`, `(define x 5)`);
  **любая другая — команда**: слова через пробел, первое = имя, остальные = строковые аргументы, т.е.
  `ls /etc` ≡ `(ls "/etc")`. Голые слова = нулевое трение шелла; `(...)` = полный Lisp. Гомоиконно
  (команда — форма применения со строковыми аргументами). Командный режим — в S2b (в S2a REPL пока
  чисто-Lisp).
- **Эффекты — БЕЗ trait `Host` (оказалось проще).** Планировали инъекцию `Host` в `Interp` (как
  `import`→`ModuleLoader`), но не понадобилось: эффектные команды — обычные `fn(&[Value])`-builtins,
  определённые В БИНАРЕ, дёргают синкаллы напрямую (`sys::start_cap` даёт caps ambient процессу,
  `px::*`/`sys::write` — глобальны; состояние не нужно). Бинарь регистрирует их в окружение REPL
  (`env.define(name, Value::Builtin(...))` — всё публично). `vvsh-core` остаётся ЧИСТЫМ: конфиг
  использует `root_env` (без команд), команды — только в шелл-окружении. (S2b — сделано так.)
- **Ни root, ни юзеров** — capability-модель ([[void-no-users-root]]): шелл владеет своими cap'ами,
  никакого `sudo`/identity. Больше прав — только через `GRANT`.

## Разбиение

- **S2a** ✅ (Веха 78) — интерактивный Lisp-REPL, окружение живёт между строками; чисто-вычислительный.
- **S2b** ✅ (Веха 79) — эффектные команды (`ls`/`cat`/`echo`/`run`), синтаксис голых слов, спавн
  программ по имени (PATH). Теперь это шелл.
- **S2c** ✅ (Вехи 80–81) — ч.1: конвейеры на ЗНАЧЕНИЯХ (`ls | grep vv | count`); ч.2: `cd`/cwd +
  относительные пути, `$VAR` (шелл-переменные = Lisp-переменные), `map`/`filter`, line-editor
  (история ↑/↓, курсор ←/→/Home/End, backspace/Del). Фаза шелла — usable daily driver.

## Веха 78 — S2a: интерактивный Lisp-REPL на VOID

`run vvsh repl` — читает строки, вычисляет каждую как Lisp, печатает результат; **окружение
ПЕРСИСТЕНТНО между строками** (`(define x 5)` → потом `(* x x)` → 25). Доказывает: язык работает
интерактивно на VOID.

Почти не трогает `vvsh-core` — в нём уже есть `Interp::eval(expr, &env)` и `root_env()`; REPL держит
ОДНО окружение сессии и гоняет по нему строки (`Interp::new(&NoLoader)` — эффектов пока нет). В бинаре
`vvsh`: цикл `cmd_repl` + минимальный `read_line` (эхо + backspace; стрелки/история — позже) +
печать `Value` через `Display`. Выход — `(exit)`/`exit`/Ctrl-D → назад в vsh (vsh = спасательный
внешний шелл; упадёт vvsh — vsh ловит).

Запуск из vsh через существующий `run` (SYS_EXEC): пока vvsh крутится, vsh ПАРКУЕТСЯ (ждёт ребёнка),
консольный ввод идёт vvsh; по выходу vvsh — vsh продолжает.

Проверка (QEMU, x86 q35 + riscv-virt): `run vvsh repl` →
`(+ 1 2)`→`3`; `(define x 5)`→`5`; `(* x x)`→`25` (**x помнится между строками**);
`(define (sq n) (* n n))`→`#<замыкание>`; `(sq 9)`→`81`; `(if (= x 5) "пять" "нет")`→`"пять"`;
`(append (list 1 2) (list 3))`→`(1 2 3)`; `(car (cdr (list 10 20 30)))`→`20`;
`(nope)`→`ошибка: неизвестный символ 'nope'` (не роняет REPL); `(exit)` → назад в vsh (`echo` после —
vsh снова принял управление). Обе арх 0 предупреждений, ядро не менялось.

## Веха 79 — S2b: эффектные команды + синтаксис голых слов (vvsh = шелл)

REPL стал настоящим шеллом. **Гибридный ввод:** строка с `(`/`'` — Lisp-выражение (eval + печать
непустого результата); иначе — КОМАНДА (голые слова).

**Разрешение команды** (`command_line`): первое слово — имя, остальные — строковые аргументы.
- имя связано с ВЫЗЫВАЕМЫМ (builtin/замыкание) → вызвать `(имя "арг"…)`, вывод от самой команды;
- связано со ЗНАЧЕНИЕМ и без аргументов → показать (инспекция переменной);
- НЕ связано → **спавн программы** с этим именем (как PATH: `hello` запускает программу hello).

**Команды-эффекты — builtins в бинаре** (не в vvsh-core): `ls [путь]`, `cat путь`, `echo арг…`,
`run "имя" арг…`. Обычные `fn(&[Value])`, дёргают синкаллы напрямую (caps из `start_cap` — ambient
процессу; вывод `sys::write`). Регистрируются в `shell_env()` = `root_env()` + эти команды. Они же
работают и в Lisp-режиме и КОМПОНУЮТСЯ: `(if (= (+ 1 1) 2) (echo "ok") (echo "no"))`. `vvsh-core`
не менялся (конфиг остаётся чистым — `root_env` без команд).

Разница литерал vs переменная (ровно как bash `echo x` vs `echo $x`): `echo g` (команда, аргумент
буквальный) → `g`; `(echo g)` (Lisp, `g` — символ/переменная) → её значение.

Проверка (QEMU, x86 q35 + riscv-virt): `ls /` (список файлов), `cat /shtest.txt` → `hello-from-file`,
`echo привет мир` → `привет мир`, `(define g "expr-hi")`→`"expr-hi"`, `echo g`→`g`, `(echo g)`→
`expr-hi`, `hello` → **спавн программы** (`SYS_EXEC 'hello'`, вывод программы), `(if (= (+ 1 1) 2)
(echo "math-ok") …)`→`math-ok`, `g`→`"expr-hi"` (инспекция), `nosuchcmd`→`команда не найдена`,
`(exit)`→назад в vsh. Обе арх 0 предупреждений, ядро не менялось.

## Веха 80 — S2c (часть 1): конвейеры на ЗНАЧЕНИЯХ (`ls | grep vv | count`)

В VOID нет захвата stdout/каналов (проверено) → конвейер делаем **родным для Lisp способом — на
ЗНАЧЕНИЯХ**, а не на байтах (как PowerShell/nushell: команды отдают объекты, хост рендерит). Это
идеально ложится на гомоиконный store: течёт `Value`, а не текст.

- **`|` (thread-last)** — спец-форма в vvsh-core: `(| seed этап…)`, значение течёт ПОСЛЕДНИМ
  аргументом каждого этапа. `(| (ls "/") (grep "vv") count)` = `(count (grep "vv" (ls "/")))`. Этап-
  список `(f a…)` → `(f a… acc)`; этап-символ `f` → `(f acc)`.
- **`ls` теперь ВОЗВРАЩАЕТ список** имён (было: печатал+nil) — чтобы течь в конвейер; на верхнем
  уровне REPL сам рендерит.
- **`grep`** (builtin в бинаре): `(grep "подстрока" список)` → отфильтрованный список строк.
- **`length`/`count`** (builtins в vvsh-core, `count` — алиас): длина списка.
- **Хост-рендеринг** (`render`): `()` — ничего; список — по элементу на строку (строки без кавычек);
  прочее — каноничной формой. Применяется к результату И команд, И выражений на верхнем уровне.
  (Смена модели с S2b: команды-данные ОТДАЮТ значение, а не печатают; `echo`/`cat` — по-прежнему
  прямой вывод, они «терминальные».)

Конвейер чист (нет захвата байтов), типизирован (течёт структура), компонуется с любым Lisp:
`(| (ls "/") (grep "vv") count)`. Проверено (QEMU, x86 q35 + riscv-virt): `ls /` → файлы построчно;
`(| (ls "/") (grep "vv"))` → `a.vv b.vv c.vv nope.vv`; `… count` → `4`; `(| (ls "/") (grep ".txt"))`
→ `.txt`-файлы; `(| (ls "/") count)` → `11`; `(length (ls "/"))` → `11`; `(| (list 10 20 30 40)
count)` → `4`. Host-тестов 14 (добавлен `length_and_pipe`). Обе арх 0 предупреждений, ядро не менялось.

## Веха 81 — S2c (часть 2): cd/cwd, $VAR, map/filter, line-editor — фаза ШЕЛЛА завершена

Довели шелл до usable daily driver.

- **cwd/cd + относительные пути.** Глобальный cwd сессии (`static CWD` под `UnsafeCell`+`AtomicUsize` —
  процесс однопоточный, гонок нет). `resolve(rel)` → абсолютный нормализованный (`.`/`..`/`//`).
  `cd [путь]` (builtin; без пути — в корень; проверяет, что каталог), `pwd`; `ls`/`cat` резолвят
  относительный путь. Приглашение показывает cwd: `vvsh:/work> `.
- **`$VAR` — шелл-переменные = Lisp-переменные.** В командном режиме аргумент `$name` подставляется
  значением Lisp-переменной `name` (`(define name "voidfox")` → `echo hi $name` → `hi voidfox`);
  несвязано → пустая строка (как bash). Единый namespace: `$x` (команда) и `x` (Lisp) — одно и то же.
- **`map`/`filter` — спец-формы в vvsh-core** (используют `self.apply`; не потребовали смены сигнатуры
  builtin'ов). `sf_pipe` переписан на «вжатие» `(quote acc)` → в конвейере годятся и функции, и
  спец-формы: `(| (list 1 2 3 4) (filter (lambda (x) (= x 2))) count)` → `1`.
- **line-editor** (свой в vvsh, vsh не трогаем): история ↑/↓ (кольцо `HISTN=8`), курсор ←/→,
  Home/End, backspace/Delete, Ctrl-C/Ctrl-D; байт-ориентированный (ASCII точен). `render` печатает
  строки без кавычек (шелл-дружелюбно), список — построчно, `()` — ничего.

Проверка (QEMU, x86 q35 + riscv-virt): `pwd`→`/`; `cd /work`→приглашение `vvsh:/work>`; `cd ..`→`/`;
`(define name "voidfox")` + `echo hi $name`→`hi voidfox`; `(map (lambda (x) (* x x)) (list 1 2 3))`→
`1 4 9` построчно; `(| (list 1 2 3 4) (filter (lambda (x) (= x 2))) count)`→`1`; `echo recall-test`
затем **стрелка вверх** → повтор той же команды (история). Host-тестов 15 (`map_and_filter`). Обе арх
0 предупреждений, ядро не менялось.

**Фаза vvsh (ADR 0006) — конфиг (M1) + шелл (S2) — закрыта.** vsh остаётся внешним спасательным
шеллом. Дальше по роадмапу — графика ([[0007-graphics-native-compositor]], п. 9).

## Веха 82 — консольная жизнь: авто-запуск vvsh + тихие логи

Мелочи, без которых система не ощущается живой.

- **Авто-запуск vvsh.** vsh при старте сам поднимает `vvsh repl` (`px::spawn_args(xcap, "vvsh",
  "repl")` после приветствия); вышел/упал vvsh → управление возвращается в vsh (внешний спасатель),
  зайти снова — `run vvsh repl`. Строку `shell` конфига НЕ трогаем — vsh остаётся login-шеллом, vvsh
  живёт поверх него. Бут теперь сразу приводит в рабочий Lisp-шелл.
- **Тихие логи.** Трейс ядра ([ipc]/[obj]/[mm]/[exec]/…) — это `vprintln!` под `VERBOSE`; был вкл по
  умолчанию и сбивал вывод команд. Теперь `proc::set_verbose(false)` перед интерактивной сессией
  (бут-инфо `println!` остаётся). Переключатель на лету: синкалл `SYS_LOG(on)` (№35, без гейта —
  отладочная удобность) + команда `log on`/`log off` в vvsh и vsh.
- **Пакеты (разобрались, [[void-pkg]]).** База (`ls/cat/grep/cd/pwd/echo/|/map/filter`) встроена в
  vvsh — ставить не надо. Больше программ — хостовой сборкой (nixpkgs `voidify`, uutils) + мост
  `void-store-import` → `bin/<arch>/name`, на устройстве `run name`. On-device менеджер — будущая
  фаза. В README добавлен раздел «Программы и пакеты».

Проверка (QEMU, x86 q35 + riscv-virt): бут → vvsh стартует САМ (без ввода); интерактив тих (0 строк
трейса на `ls /`); `log on` → трейс появляется (4 строки на `ls /`), `log off` → снова 0; `(exit)` →
vsh принимает управление. Обе арх 0 предупреждений.

## Веха 83 — полировка vvsh: clear/help + цвет + поток выхода

По фидбеку: (1) добавлены команды `clear` (ANSI-очистка) и `help` (справка vvsh: команды + Lisp-
шпаргалка, жёлтая команда/выравнивание как в vsh); (2) **цветной промпт** как у vsh — зелёный `vvsh`
(`\x1b[1;32m`) + синий каталог (`\x1b[1;34m`) + `> ` (ANSI нулевой ширины → редактор считает колонки
верно); приветствие vvsh упоминает `help`; (3) **убран дамп vsh-help после выхода из vvsh** — раньше
vsh печатал полный `print_help` в bootpath (виден только после выхода vvsh, сбивал с толку); теперь
после возврата в vsh — короткая подсказка (`help` — команды, `run vvsh repl` — обратно), полная
справка по команде `help`. Стартовое сообщение — приветствие vvsh при его старте (в т.ч. авто-запуск).
Проверено на обеих арх: цветной промпт, `help`/`clear` (не «команда не найдена»), нет vsh-дампа.

## Веха 84 — перенос всех команд vsh в vvsh

vvsh перестал зависеть от vsh по функционалу: все команды спасательного шелла теперь есть и в vvsh
(builtins-эффекты, дёргают синкаллы напрямую; права из start_cap 0/1/2 = posixfs/store/net — vvsh
наследует их при exec от vsh). Добавлены: `roots` (сырые корни store), `mkdir`/`rm`/`tail`/`mv`
(каталоги/файлы через posixfs), `ping A.B.C.D` (ICMP через net-srv, start-cap 2), `thaw` (разморозка
образа), `switch`/`sysdef` (поколения), `rebuild`/`gens`/`init-config` (конфиг — прямо в REPL, а не
только `run vvsh …`). `echo TEXT > FILE` дорос до редиректа (голое слово `>` включает запись в файл,
как в vsh). Логика `init-config`/`rebuild`/`gens` вынесена в общие `run_*`, которые зовут и
подкоманды (`sys::exit`), и REPL-builtins (`Ok(nil)`) — без дублирования. `help` обновлён.

Проверено (QEMU, x86 q35 + riscv-virt, свежий диск): `init-config` сеет `/etc/system/*.vv`,
`ls /etc/system` их показывает; `mkdir /d` → `echo privet > /d/a` → `cat`/`tail` → `mv` → `ls` → `rm`
проходят; `roots` печатает корни (bin/<arch>/*, system/*, f/etc/system/*); `rebuild` → `gen3`,
`gens` метит активное `*`; `ping 10.0.2.2` отвечает. Обе арх: 0 предупреждений.

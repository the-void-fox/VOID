# vvsh — фаза ШЕЛЛА: интерактивный REPL (пруф №2)

Вторая половина ADR 0006: vvsh как интерактивный шелл-REPL поверх того же гомоиконного Lisp'а
([[vvsh-lang]]), что и конфиг ([[vvsh-config-layout]]). Один язык для конфига и шелла, без порта bash.

## Принятые решения (обсуждено)

- **vsh остаётся ВСЕГДА — внешний спасательный шелл.** vvsh НЕ заменяет vsh. Модель: vsh = внешний/
  login-шелл (минимальный, надёжный), **vvsh repl = богатый под-шелл**, в который заходишь из vsh
  (`run vvsh repl`) и возвращаешься по выходу/падению. Упадёт vvsh — vsh ловит обратно. Строку `shell`
  в конфиге не трогаем; никакой рискованной замены.
- **Гибридный синтаксис (eshell/rc).** Строка, начинающаяся с `(` — Lisp (`(+ 1 2)`, `(define x 5)`);
  **любая другая — команда**: слова через пробел, первое = имя, остальные = строковые аргументы, т.е.
  `ls /etc` ≡ `(ls "/etc")`. Голые слова = нулевое трение шелла; `(...)` = полный Lisp. Гомоиконно
  (команда — форма применения со строковыми аргументами). Командный режим — в S2b (в S2a REPL пока
  чисто-Lisp).
- **Эффекты — БЕЗ trait `Host` (оказалось проще).** Планировали инъекцию `Host` в `Interp` (как
  `import`→`ModuleLoader`), но не понадобилось: эффектные команды — обычные `fn(&[Value])`-builtins,
  определённые В БИНАРЕ, дёргают синкаллы напрямую (`sys::start_cap` даёт caps ambient процессу,
  `px::*`/`sys::write` — глобальны; состояние не нужно). Бинарь регистрирует их в окружение REPL
  (`env.define(name, Value::Builtin(...))` — всё публично). `vvsh-core` остаётся ЧИСТЫМ: конфиг
  использует `root_env` (без команд), команды — только в шелл-окружении. (S2b — сделано так.)
- **Ни root, ни юзеров** — capability-модель ([[void-no-users-root]]): шелл владеет своими cap'ами,
  никакого `sudo`/identity. Больше прав — только через `GRANT`.

## Разбиение

- **S2a** ✅ (Веха 78) — интерактивный Lisp-REPL, окружение живёт между строками; чисто-вычислительный.
- **S2b** ✅ (Веха 79) — эффектные команды (`ls`/`cat`/`echo`/`run`), синтаксис голых слов, спавн
  программ по имени (PATH). Теперь это шелл.
- **S2c** — конвейеры (`ls | grep`, требует захвата stdout — плюмбинг через posixfs/каналы), переменные
  окружения; возможно авто-заход в vvsh из vsh на логине (vsh всё равно остаётся спасательным).

## Веха 78 — S2a: интерактивный Lisp-REPL на VOID

`run vvsh repl` — читает строки, вычисляет каждую как Lisp, печатает результат; **окружение
ПЕРСИСТЕНТНО между строками** (`(define x 5)` → потом `(* x x)` → 25). Доказывает: язык работает
интерактивно на VOID.

Почти не трогает `vvsh-core` — в нём уже есть `Interp::eval(expr, &env)` и `root_env()`; REPL держит
ОДНО окружение сессии и гоняет по нему строки (`Interp::new(&NoLoader)` — эффектов пока нет). В бинаре
`vvsh`: цикл `cmd_repl` + минимальный `read_line` (эхо + backspace; стрелки/история — позже) +
печать `Value` через `Display`. Выход — `(exit)`/`exit`/Ctrl-D → назад в vsh (vsh = спасательный
внешний шелл; упадёт vvsh — vsh ловит).

Запуск из vsh через существующий `run` (SYS_EXEC): пока vvsh крутится, vsh ПАРКУЕТСЯ (ждёт ребёнка),
консольный ввод идёт vvsh; по выходу vvsh — vsh продолжает.

Проверка (QEMU, x86 q35 + riscv-virt): `run vvsh repl` →
`(+ 1 2)`→`3`; `(define x 5)`→`5`; `(* x x)`→`25` (**x помнится между строками**);
`(define (sq n) (* n n))`→`#<замыкание>`; `(sq 9)`→`81`; `(if (= x 5) "пять" "нет")`→`"пять"`;
`(append (list 1 2) (list 3))`→`(1 2 3)`; `(car (cdr (list 10 20 30)))`→`20`;
`(nope)`→`ошибка: неизвестный символ 'nope'` (не роняет REPL); `(exit)` → назад в vsh (`echo` после —
vsh снова принял управление). Обе арх 0 предупреждений, ядро не менялось.

## Веха 79 — S2b: эффектные команды + синтаксис голых слов (vvsh = шелл)

REPL стал настоящим шеллом. **Гибридный ввод:** строка с `(`/`'` — Lisp-выражение (eval + печать
непустого результата); иначе — КОМАНДА (голые слова).

**Разрешение команды** (`command_line`): первое слово — имя, остальные — строковые аргументы.
- имя связано с ВЫЗЫВАЕМЫМ (builtin/замыкание) → вызвать `(имя "арг"…)`, вывод от самой команды;
- связано со ЗНАЧЕНИЕМ и без аргументов → показать (инспекция переменной);
- НЕ связано → **спавн программы** с этим именем (как PATH: `hello` запускает программу hello).

**Команды-эффекты — builtins в бинаре** (не в vvsh-core): `ls [путь]`, `cat путь`, `echo арг…`,
`run "имя" арг…`. Обычные `fn(&[Value])`, дёргают синкаллы напрямую (caps из `start_cap` — ambient
процессу; вывод `sys::write`). Регистрируются в `shell_env()` = `root_env()` + эти команды. Они же
работают и в Lisp-режиме и КОМПОНУЮТСЯ: `(if (= (+ 1 1) 2) (echo "ok") (echo "no"))`. `vvsh-core`
не менялся (конфиг остаётся чистым — `root_env` без команд).

Разница литерал vs переменная (ровно как bash `echo x` vs `echo $x`): `echo g` (команда, аргумент
буквальный) → `g`; `(echo g)` (Lisp, `g` — символ/переменная) → её значение.

Проверка (QEMU, x86 q35 + riscv-virt): `ls /` (список файлов), `cat /shtest.txt` → `hello-from-file`,
`echo привет мир` → `привет мир`, `(define g "expr-hi")`→`"expr-hi"`, `echo g`→`g`, `(echo g)`→
`expr-hi`, `hello` → **спавн программы** (`SYS_EXEC 'hello'`, вывод программы), `(if (= (+ 1 1) 2)
(echo "math-ok") …)`→`math-ok`, `g`→`"expr-hi"` (инспекция), `nosuchcmd`→`команда не найдена`,
`(exit)`→назад в vsh. Обе арх 0 предупреждений, ядро не менялось.

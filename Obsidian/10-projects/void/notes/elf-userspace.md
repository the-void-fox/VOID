# Веха 23 — userspace целиком в ELF из store

Первая веха Фазы 4 ([[0004-void-pkg|ADR 0004]]) и пререквизит всего дальнейшего: до неё
почти весь код процессов жил в секции `.user` образа ядра ([[user-mode]]) — компилировался как
код ядра, а исполнялся в U-mode. Теперь **все 13 программ** — самостоятельные статические
ELF64/RISC-V в объектном store; секции `.user` не существует, у ядра нет ни одной страницы с
флагом U. Код в U-mode приходит единственным путём: корень `bin/<имя>` → content-id → байты из
store → [[exec-from-store|elf::load]].

## 23.1 — крейт `programs/user`

Один крейт вне workspace ядра: библиотека `void-user` (src/lib.rs) + бинарь на программу
(src/bin/*). В библиотеке — ЕДИНСТВЕННОЕ место, где userspace видит `ecall`: типизированные
шимы всех 17 syscall'ов, POSIX-shim (`posix::open/read/write/close/readdir/spawn` + `cat`/
`echo_to`), общий `#[panic_handler]` (exit 101). Программы: `vsh`, `posixfs`, `mini-sh`,
`blk-srv/cli`, `obj-srv/cli`, `cap-srv/cli`, `busy`, `heap`, `crash`, `hello` (переехал из
`programs/hello`). Все — обычный Rust: слайсы, `copy_from_slice`, zero-init массивы — 5–13 КиБ
на бинарь (opt-level="z" + LTO).

## 23.2 — сев по хэшу: обновление системы = смена корня

`kernel/build.rs` собирает крейт одним дочерним `cargo build` (свой target-dir в OUT_DIR) и
отдаёт пути ELF через `cargo:rustc-env`; в образе ядра байты живут только как СЕМЕНА
(`include_bytes!`). На загрузке `seed_programs()`: `put(семя)` (дедуп бесплатен) → сравнить
content-id с корнем `bin/<имя>` →
- совпал — «актуально», диск и есть истина, семя не участвует;
- корня нет — «посеяно» (первая загрузка);
- разошёлся — «обновлено»: корень атомарно переезжает, старые байты становятся мусором и
  уходят в GC. **Это и есть механизм обновления системы** — ровно та смена корня, на которой
  стоит [[0004-void-pkg|void-pkg]]. Проверено вживую: изменил hello → `12 актуально,
  1 обновлено`, исполнилась новая версия из store.

`kmain` запускает все демо через `spawn_prog("bin/…")` — тот же путь, что `SYS_EXEC` у vsh.

## 23.3 — похороны `.user` и их плоды

Удалены: `kernel/src/user.rs` (1200 строк сырых указателей), секция в `linker.ld`, маппинг
`U|R|X` в `paging::init`, `proc::spawn` (остался только `spawn_elf`). Плоды:

- **Мины обезврежены** ([[process-heap|Веха 22]] «Грабли»): memset/memcpy теперь из
  compiler_builtins самого бинаря, jump-таблицы — в его собственной .rodata (страницы U).
  Ухищрения (`MaybeUninit`, метаданные в куче из-за memset) больше не нужны — persональность
  переписана обычными массивами.
- **Ядро на `opt-level = 2`** (dev-профиль): предупреждение Вехи 22 снято, MMIO всюду
  volatile — сборка+все демо+2 прогона чисты. Кадры стека ужались, QEMU заметно быстрее.
- **Целостность модели**: у ядра и userspace не осталось общих страниц вообще — граница
  только ABI (`ecall`), как и положено ([[0002-persistent-content-addressed-capability-core|ADR 0002]]).

## 23.4 — честные шлюзы (обещание Вехи 22 закрыто)

Ограничение «IPC-копии в ленивые буферы молча пропускают немапленные страницы» снято:
`ensure_heap_range` теперь стоит во ВСЕХ местах, где ядро само трогает память процесса —
`deliver_request`/`REPLY` (оба конца), `SYS_WRITE`/`SYS_READ`, буферы и `id`/имена корней в
`OBJ_*`, `BLK_*`, `SYS_EXEC`. Программа может держать любой буфер в ленивой куче — ядро
доотобразит страницы до доступа (S-фолт по-прежнему фатален, поэтому заранее), а при
исчерпании фреймов честно откажет (MAX / нулевая доставка).

## Грабли

- `busy` и kernel-задача `writer`: на opt-level>0 суммирующий busy-loop — константа времени
  компиляции; спасает `core::hint::black_box` на каждой итерации (и рост счётчика до 20М —
  Oz-код цикла в разы плотнее, чем был -O0).
- Env-переменные не терпят дефисов: `mini-sh` → `PROG_MINI_SH` (to_uppercase + replace).
- Крейт с lib+bins получает линкер-скрипт через `cargo:rustc-link-arg-bins` (не `-link-arg`,
  rlib библиотеки не линкуется).

## Проверено (два прогона, один диск, + прогон обновления)

1. Свежий диск: `13 посеяно`; все демо Вех 8–22 идут из ELF (вытеснений 46, heap/crash
   честны); vsh: `ls · cat motd.txt · echo … > m23.txt · cat · run bin/hello · exit`.
2. Перезагрузка: `13 актуально, 0 посеяно, 0 обновлено` — те же content-id (32579bfeef… у
   hello в обоих прогонах); greeting/motd.txt/m23.txt на месте; cap `[r-g--]` восстановлен из
   `.cspace` без повторной выдачи; PANIC 0.
3. Изменённый hello: `1 обновлено`, из store исполняется новая версия.

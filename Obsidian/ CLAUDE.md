# CLAUDE.md — Obsidian Dev Vault

Это vault для заметок по коду и проектам: dev notes, ADR (Architecture Decision Records),
TODO/задачи, справочные заметки. Код живёт в отдельной директории `Code/` рядом, этот vault —
`Obsidian/`. Здесь только Markdown.

## Структура vault

```
.
├── 00-inbox/          # Необработанные заметки. Всё новое и нерассортированное падает сюда.
├── 10-projects/       # Одна папка на проект. Внутри: README, ADR, заметки по проекту.
│   └── <project>/
│       ├── README.md  # Обзор проекта: что это, статус, ссылки на код
│       ├── adr/       # ADR этого проекта (см. шаблон ниже)
│       └── notes/     # Свободные заметки по проекту
├── 20-reference/      # Долгоживущие справочные заметки: сниппеты, how-to, концепты
├── 30-todo/           # Задачи. todo.md — общий список, плюс заметки по крупным задачам
├── daily/             # Ежедневные заметки YYYY-MM-DD.md
├── templates/         # Шаблоны заметок (ADR, project, daily, reference)
└── .claude/commands/  # Slash-команды Claude Code
```

## Конвенции

### Именование файлов
- kebab-case для имён: `ili9341-init-debug.md`, не `ILI9341 Init Debug.md`.
- ADR: `adr/NNNN-short-title.md` с zero-padded номером — `0001-flat-grid-in-core.md`.
- Daily: строго `YYYY-MM-DD.md`.
- Имя файла = смысл заметки. Без `Untitled`, без дат в произвольных заметках.

### Ссылки
- ВСЕГДА `[[wikilinks]]`, никогда markdown-ссылки на внутренние заметки.
- Ссылайся на заметку по имени файла без расширения: `[[ili9341-init-debug]]`.
- Заголовки секций линкуй так: `[[note#Заголовок]]`.

### Frontmatter
Каждая заметка (кроме daily) начинается с YAML frontmatter:

```yaml
---
title: Человекочитаемый заголовок
created: 2026-06-30
tags: [project/ereb, rust, debug]
status: active   # active | done | archived | idea
---
```

- `status` обязателен для заметок в `10-projects/` и `30-todo/`.
- Теги иерархические через `/`: `project/ereb`, `lang/rust`, `topic/embedded`.

### Атомарность
- `20-reference/` — атомарные заметки: одна идея = одна заметка. Линкуй вместо дублирования.
- `10-projects/.../notes/` — можно длиннее, это рабочий лог.

## Правила для Claude

- **НИКОГДА не трогай `.obsidian/`** — там конфиг плагинов, тем, hotkeys. Любая правка ломает Obsidian.
- **Не редактируй `templates/`** без явной просьбы — это эталоны.
- Создавая новую заметку, ВСЕГДА добавляй frontmatter по схеме выше.
- Создавая заметку в проекте, проверь `10-projects/<project>/README.md` на контекст и конвенции проекта.
- Не дублируй контент: если концепт уже есть в `20-reference/`, ставь `[[ссылку]]`.
- Новое и нерассортированное → `00-inbox/`. Не раскидывай по папкам наугад.
- При массовых операциях (rename, реструктуризация, расстановка ссылок) — сначала кратко опиши план, потом выполняй.
- Язык заметок — как у пользователя (RU/UA/EN), не переводи существующие.

## Полезные операции, в которых ты силён здесь

- Расстановка backlinks между связанными заметками.
- Вынос атомарных идей из длинного рабочего лога в `20-reference/`.
- Генерация ADR из обсуждения архитектурного решения.
- Поиск orphan-заметок (без входящих ссылок) и дубликатов.

# Закрытые вехи: отчёты

Разгрузка [[todo]]: раздел «Сейчас» копил подробные отчёты о закрытых вехах и перестал показывать
то, ради чего он есть, — что делается ПРЯМО СЕЙЧАС. Отчёты переехали сюда без изменений, порядок
обратно-хронологический. Вехи 87–88 (higher-half и карта памяти регионами) описаны в [[todo]] в
своих местах роадмапа — Фаза 6.

- [x] **Веха 126.4 — зависание после нескольких переездов камеры — закрыта** ([[direction-flag]]):
  процессор при входе в trap не сбрасывает `DF`, и он приезжал в ядро взведённым из userspace
  (`memmove` для перекрывающихся копий делает `std; rep movsb; cld` — прерывание попадало ВНУТРЬ
  этого окна). Дальше `memcpy` в ядре шёл назад и затирал собственный адрес возврата нулями.
  Лечение — `cld` первой инструкцией `trap_common`, как в Linux. Обе прежние версии диагноза
  (утечка памяти; путь «уборка store → коммит») были **неверны**: уборка лишь чаще подводила к
  тому единственному `memcpy`. Подпорка (порог `obj_gc` 12 МиБ) снята, порог вернулся к 4 МиБ.

- [x] **Веха 86 — настоящие часы (RTC) и источник случайности — закрыта** ([[clock]], старт Фазы 6 «фундамент»): у системы появилось ВРЕМЯ и ЭНТРОПИЯ — две вещи, которых не было вовсе. Было: монотонный счётчик с загрузки, а «настенные часы» — **выдуманная база 2026-07-01 + uptime** в порте std; `CLOCK_REALTIME` и `CLOCK_MONOTONIC` в [[linux-abi]] возвращали одно и то же; `getrandom` — xorshift от счётчика. **Стало:** контракт `arch/` вырос на `wall_clock_unix_ns` + `hw_random_u64`; **x86** — драйвер CMOS RTC (`rtc.rs`: порты 0x70/0x71, ожидание UIP, два согласованных чтения, BCD/binary и 12/24ч из регистра B, век из 0x32); **riscv** — `google,goldfish-rtc`, адрес НЕ зашит, а найден в DTB тем же FDT-парсером Вехи 85 (`dtb_find_compatible`), страницу MMIO отображает `paging::init`. Общий `clock.rs` читает часы ОДИН раз на загрузке и ведёт `realtime = база + uptime` (поход в RTC стоит микросекунд, счётчик — одну инструкцию); там же единственный `TICK_NS` (дубль из `linux.rs` убран) и `civil_from_unix`. Случайность — `random.rs`: `RDRAND` (x86, с проверкой CPUID) + **пул событий** (`stir` подмешивает джиттер пробуждений по вводу и прерываний диска — БЕЗ замков, только атомики: замок в IRQ = дедлок), выдача через BLAKE3. Граница: `SYS_TIME` (№36, kind 0=wall/1=monotonic) и `SYS_RANDOM` (№37). Потребители: баннер загрузки печатает дату, vvsh получил `date` и `random [N]`, `clock_gettime` наконец РАЗЛИЧАЕТ realtime/monotonic, `getrandom` linux-abi идёт в общий источник, а в порте std (`vendor/rust`) убрана фиктивная база — `SystemTime::now` спрашивает ядро. Проверено (QEMU x86 q35 + riscv-virt): `[time] 2026-07-29 15:08:32 UTC (RTC)` совпадает с хостом на обеих арх; `date` в vvsh — точное время; `random` даёт разные значения подряд (x86 — RDRAND, riscv — пул); `run hello-std` печатает `SystemTime: 1785338426 с Unix` при хосте 1785338423 (x86) и то же на riscv. Обе арх 0 предупреждений. Осталось (записано): часовых поясов нет (всё UTC), ход часов не корректируется (`TICK_NS` под QEMU), на riscv энтропия не криптографическая до virtio-rng, времён у файлов в posixfs по-прежнему нет.

- [x] **Веха 85 — поддержка гигабайтов RAM — закрыта** ([[platform]]): реальный объём памяти + huge-страницы в direct-map. Детект: x86 — **PVH-memmap** от QEMU (`discover_pvh`, magic 0x336ec578) в дополнение к multiboot `mem_upper`; riscv — **`/memory` из DTB** (a1, минимальный FDT-парсер). direct-map теперь стелется **2-МиБ huge-страницами** (x86 PD-лист с PS; riscv мегастраница-лист уровня 1) — гигабайты отображаются дёшево; чанки образа ядра кладём постранично (вырез под W^X, `map_direct`). Потолки несимметричны из-за раскладки VA: **riscv 2 ГиБ** (RAM с 0x8000_0000, user ниже — не сталкиваются), **x86 1 ГиБ** (direct-map тождественный, а user-регион всех программ прибит линкером к [1 ГиБ, 2 ГиБ) — RAM-отображение обязано кончаться на 1 ГиБ; больше — только higher-half ядро). Щит `PTE_PS` в обходчиках x86 (translate/page_info/free_private). Проверено в QEMU на обеих арх: `-m 2G` → riscv видит 2048/использует 2048, x86 видит 2047/использует 1024; загрузка, exec ELF, ping, checkpoint/thaw (`page_info` под huge-пейджингом) — чисто; регрессия `-m 128M` — чисто. 0 предупреждений.

- [x] **Веха 84 — перенос всех команд vsh в vvsh — закрыта** ([[vvsh-shell]]): vvsh получил все команды спасательного vsh (builtins-эффекты, права из start_cap 0/1/2 = posixfs/store/net, наследуются при exec от vsh): `roots`, `mkdir`/`rm`/`tail`/`mv`, `ping A.B.C.D` (ICMP через net-srv), `thaw`, `switch`/`sysdef`, `rebuild`/`gens`/`init-config` (конфиг прямо в REPL). `echo TEXT > FILE` дорос до редиректа (голое слово `>`). Общая логика `init-config`/`rebuild`/`gens` вынесена в `run_*` (зовут и подкоманды `sys::exit`, и REPL-builtins `Ok(nil)`). `help` обновлён. Проверено на обеих арх (свежий диск): все команды проходят, `rebuild`→gen3, `ping 10.0.2.2` отвечает. 0 предупреждений.

- [x] **Веха 83 — полировка vvsh: clear/help + цвет + поток выхода — закрыта** ([[vvsh-shell]], по фидбеку): (1) команды `clear` (ANSI-очистка) и `help` (справка vvsh: команды + Lisp-шпаргалка, жёлтая команда/выравнивание как в vsh); (2) **цветной промпт** как у vsh — зелёный `vvsh` (`\x1b[1;32m`) + синий каталог (`\x1b[1;34m`) + `> ` (ANSI нулевой ширины → редактор считает колонки верно), приветствие упоминает `help`; (3) **убран дамп vsh-help после выхода из vvsh** (раньше vsh печатал полный print_help в bootpath — виден только после выхода vvsh, сбивал с толку) → теперь короткая подсказка при возврате в vsh, полный `help` — по команде; стартовое сообщение = приветствие vvsh при старте (в т.ч. авто-запуск). Проверено (QEMU x86 q35 + riscv-virt): цветной промпт, `help`/`clear` работают (не «команда не найдена»), нет vsh-дампа после выхода. Обе арх 0 предупреждений.

- [x] **Веха 82 — консольная жизнь: авто-запуск vvsh + тихие логи (`log on/off`) + пакеты в README — закрыта** ([[vvsh-shell]]): «мелочи», без которых система не живая. **(1) Авто-запуск vvsh:** vsh (внешний СПАСАТЕЛЬНЫЙ шелл) при старте сам поднимает `vvsh repl` (`run vvsh repl` руками больше не нужно); вышел/упал vvsh → управление возвращается в vsh, зайти снова — `run vvsh repl`. Строку `shell` конфига не трогаем (vsh остаётся login-шеллом). **(2) Логи:** трейс ядра ([ipc]/[obj]/[mm]/[exec]/…) — это `vprintln!` под `VERBOSE` (было по умолчанию ВКЛ → сбивало вывод команд); теперь `proc::set_verbose(false)` перед интерактивной сессией (тихо по умолчанию, бут-инфо `println!` остаётся), + синкалл `SYS_LOG(on)` (№35, без гейта — отладочная удобность) и команда `log on`/`log off` в vvsh И vsh для переключения на лету. **(3) Пакеты (разобрались):** базовый консольный набор (ls/cat/grep/cd/pwd/echo/`|`/map/filter) ВСТРОЕН в vvsh — ставить не надо; больше программ — хостовой сборкой (nixpkgs `voidify` Веха 36 / uutils Веха 32) + мост `void-store-import` → корень `bin/<arch>/name`, на устройстве `run name`; on-device менеджер — будущая крупная фаза. Раздел в README «Программы и пакеты» + строка про логи. Проверено (QEMU x86 q35 + riscv-virt): бут → vvsh стартует САМ (без ввода), интерактив тих (0 строк трейса на `ls /`), `log on` → трейс появляется (4 строки на `ls /`), `log off` → снова 0, `(exit)` → vsh принимает управление. Обе арх 0 предупреждений. **Система грузится сразу в рабочий Lisp-шелл, вывод чистый.** Дальше — по вкусу: полировка (motd, авто-`log` из конфига), затем графика (п. 9).

- [x] **Веха 81 — vvsh S2c (часть 2): cd/cwd + $VAR + map/filter + line-editor — фаза ШЕЛЛА завершена** ([[vvsh-shell]], пруф №2): довели шелл до usable daily driver. **cwd/cd + относительные пути:** глобальный cwd сессии (`static CWD` под `UnsafeCell`+`AtomicUsize`, процесс однопоточный), `resolve(rel)`→абсолютный нормализованный (`.`/`..`/`//`), `cd [путь]`/`pwd` (builtins; cd проверяет что каталог, без пути — в корень), `ls`/`cat` резолвят относительный путь, приглашение показывает cwd (`vvsh:/work> `). **`$VAR` = Lisp-переменные:** в командном режиме `$name` подставляется значением Lisp-переменной (`(define name "voidfox")` → `echo hi $name` → `hi voidfox`; несвязано→пусто, как bash; единый namespace). **`map`/`filter`:** спец-формы в vvsh-core (через `self.apply`, без смены сигнатуры builtin'ов); `sf_pipe` переписан на «вжатие» `(quote acc)` → в конвейере годятся и функции, и спец-формы (`(| (list 1 2 3 4) (filter (lambda (x) (= x 2))) count)`→1). **line-editor** (свой в vvsh, vsh не трогаем): история ↑/↓ (кольцо HISTN=8), курсор ←/→/Home/End, backspace/Delete, Ctrl-C/D; `render` печатает строки без кавычек. Проверено (QEMU x86 q35 + riscv-virt): `pwd`→`/`; `cd /work`→`vvsh:/work>`; `cd ..`→`/`; `echo hi $name`→`hi voidfox`; `(map …)`→`1 4 9` построчно; `(| … (filter …) count)`→`1`; `echo recall-test`+**стрелка вверх**→повтор (история). Host-тестов 15. Обе арх 0 предупреждений, ядро не менялось. **Фаза vvsh (конфиг M1 + шелл S2) ЗАКРЫТА — vvsh это самохостящийся конфиг + интерактивный Lisp-шелл на VOID.** vsh остаётся спасательным. Дальше по роадмапу — графика (п. 9).

- [x] **Веха 80 — vvsh S2c (часть 1): конвейеры на ЗНАЧЕНИЯХ (`ls | grep vv | count`) — закрыта** ([[vvsh-shell]], пруф №2): в VOID нет захвата stdout/каналов → конвейер сделан РОДНЫМ для Lisp способом — **на ЗНАЧЕНИЯХ**, не на байтах (как PowerShell/nushell: команды отдают объекты, хост рендерит; идеально ложится на гомоиконный store — течёт `Value`, а не текст). `|` — спец-форма thread-last в vvsh-core (`(| seed этап…)`, значение течёт последним аргументом; `(| (ls "/") (grep "vv") count)` = `(count (grep "vv" (ls "/")))`); `ls` теперь ВОЗВРАЩАЕТ список имён (было: печатал); `grep` — builtin в бинаре (фильтр строк по подстроке); `length`/`count` — builtins в core; хост-рендеринг `render` (список → по элементу на строку без кавычек, `()` → ничего, прочее — каноничной формой) применяется к результату команд И выражений на верхнем уровне (смена модели с S2b: команды-данные отдают значение; `echo`/`cat` — по-прежнему прямой «терминальный» вывод). Конвейер чист (нет захвата байтов), типизирован, компонуется с любым Lisp. Проверено (QEMU x86 q35 + riscv-virt): `ls /`→файлы построчно; `(| (ls "/") (grep "vv"))`→`a.vv b.vv c.vv nope.vv`; `… count`→`4`; `(| (ls "/") (grep ".txt"))`→txt-файлы; `(| (ls "/") count)`→`11`; `(length (ls "/"))`→`11`; `(| (list 10 20 30 40) count)`→`4`. Host-тестов 14 (добавлен `length_and_pipe`). Обе арх 0 предупреждений, ядро не менялось. **`ls | grep vv | count` на VOID — но на значениях.** Плюс: в README добавлена инструкция сборки ISO для флешки (`mkboot.sh`) + тесты (собрал, работает). Дальше — S2c часть 2 (cd/cwd, переменные окружения, полировка line-editor, `map`/`filter` первого класса).

- [x] **Веха 79 — vvsh S2b: эффектные команды + синтаксис голых слов (vvsh стал ШЕЛЛОМ) — закрыта** ([[vvsh-shell]], [[0006-vvsh-lisp-config-shell]], пруф №2): REPL стал настоящим шеллом. **Гибридный ввод:** строка с `(`/`'` — Lisp (eval+печать непустого результата), иначе — команда (голые слова). **Разрешение команды:** имя связано с вызываемым (builtin/замыкание) → вызвать; связано со значением без аргументов → показать (инспекция переменной); НЕ связано → **спавн программы** с этим именем (как PATH — `hello` запускает программу hello). **Приятный итог:** trait `Host` НЕ понадобился — эффектные команды (`ls`/`cat`/`echo`/`run`) это обычные `fn(&[Value])`-builtins В БИНАРЕ, дёргают синкаллы напрямую (caps из `start_cap` ambient процессу, вывод `sys::write`), регистрируются в `shell_env()`=`root_env()`+команды; **vvsh-core остался ЧИСТЫМ** (конфиг использует `root_env` без команд). Команды работают и в Lisp-режиме и КОМПОНУЮТСЯ (`(if (= (+ 1 1) 2) (echo "ok") (echo "no"))`). Разница литерал/переменная как в bash (`echo g`→`g`; `(echo g)`→значение `g`). Проверено (QEMU x86 q35 + riscv-virt): `ls /`, `cat /shtest.txt`→`hello-from-file`, `echo привет мир`, `(define g "expr-hi")`→`"expr-hi"`, `echo g`→`g`, `(echo g)`→`expr-hi`, `hello`→спавн программы (`SYS_EXEC 'hello'`), `(if …)`→`math-ok`, `g`→`"expr-hi"` (инспекция), `nosuchcmd`→не найдена, `(exit)`→vsh. Обе арх 0 предупреждений, ядро не менялось. **vvsh — интерактивный Lisp-шелл на VOID.** Дальше — S2c (конвейеры, переменные окружения, `cd`/cwd, полировка line-editor).

- [x] **Веха 78 — vvsh S2a: интерактивный Lisp-REPL на VOID (старт фазы ШЕЛЛА) — закрыта** ([[vvsh-shell]], [[vvsh-lang]], [[0006-vvsh-lisp-config-shell]], пруф №2): начата вторая половина ADR 0006 — vvsh как интерактивный шелл-REPL поверх ТОГО ЖЕ языка, что и конфиг. **Решения:** (1) vsh остаётся ВСЕГДА как внешний спасательный шелл — vvsh НЕ заменяет его: `vvsh repl` это богатый под-шелл, в который заходишь из vsh (`run vvsh repl`) и возвращаешься по выходу/падению (упадёт vvsh — vsh ловит); (2) гибридный синтаксис (строка с `(` — Lisp, иначе команда `ls /etc`≡`(ls "/etc")`) — к S2b; (3) эффекты через trait `Host` (как `import`→`ModuleLoader`) — к S2b; (4) ни root, ни юзеров — capability-модель ([[void-no-users-root]]). **S2a:** `run vvsh repl` читает строки, вычисляет как Lisp, печатает результат, **окружение ПЕРСИСТЕНТНО между строками**. Почти не трогает vvsh-core (уже есть `Interp::eval(expr,&env)`+`root_env()`; REPL держит одно окружение сессии, `NoLoader` — эффектов пока нет); в бинаре — `cmd_repl` + минимальный `read_line` (эхо+backspace) + печать `Value` через Display; выход `(exit)`/Ctrl-D → назад в vsh. Проверено (QEMU x86 q35 + riscv-virt): `(+ 1 2)`→3; `(define x 5)`→5; `(* x x)`→25 (**x помнится**); `(define (sq n) (* n n))`→#<замыкание>; `(sq 9)`→81; `(if (= x 5) "пять" "нет")`→"пять"; `(append (list 1 2) (list 3))`→(1 2 3); `(nope)`→ошибка (не роняет REPL); `(exit)`→vsh снова принял управление. Обе арх 0 предупреждений, ядро не менялось. **Язык работает интерактивно на VOID.** Дальше — S2b (trait Host + эффектные команды `run`/`ls`/`cat` + синтаксис голых слов), S2c (конвейеры).

- [x] **Веха 77 — vvsh M1c: `rebuild` (eval→поколение) + сев `/etc/system` + `gens` — фаза КОНФИГА закрыта** ([[vvsh-lang]], [[vvsh-config-layout]], фаза vvsh, п. 8): замкнут полный цикл самохостинга конфига НА УСТРОЙСТВЕ (модель «FS-источник → поколение-сборка → бут из снимка»): правишь `/etc/system/*.vv` на VOID → `rebuild` на VOID → ребут грузит пересобранный конфиг. **Хостовый Nix для системного конфига больше не нужен.** Подкоманды `vvsh` (обвязка store — start-cap 1): `init-config` сеет модульный `/etc/system/{net,services,networking,default}.vv` (тумблер сети в `net.vv` `#t`/`#f`, `default.vv` = `(define net (import "net.vv"))` + сборка `append`+`if`); `rebuild` вычисляет `default.vv` → нормализованный текст → `obj_put` (контент-адресуемо) → корень `system/gen<N>` (N=max+1) → двигает `system/current`, **с dedup** (содержимое == текущему → «нет изменений»); `gens` перечисляет `system/gen*` + метит активное `*`. vsh получил тонкие встроенные `rebuild`/`gens`. **Решение по правам:** `OBJ_GET`/`GET_ROOT` требуют READ (dedup, чтение current), а `PUT`/`SET_ROOT`/`LIST_ROOTS` — WRITE (есть у shell'а); дал админ-шеллу READ — `store:xw`→**`store:rwx`** (init.rs `DEFAULT_GEN1/2`, nix/system.nix, сеянный default.vv), т.к. чтение поколений — работа шелла, а WRITE у него уже мощнее; код **деградирует мягко** (нет READ на старом `xw`-диске → без dedup/маркера, без падений). Бут не менялся (`init.rs::boot` читает нормализованный снимок; eval только на `rebuild` → поколение = контент-адресный кэш выхода eval). Проверено (QEMU x86 q35 + riscv-virt, СВЕЖИЙ диск): `init-config`→`gens`(gen1\*,gen2)→`rebuild`(net #t→gen3)→`gens`(gen3\*)→`rebuild` снова→**«нет изменений — уже gen3» (dedup)**→`echo #f > net.vv`→`rebuild`(net #f→gen4)→`gens`(gen4\*); **ребут** того же диска → `[init] поколение 'gen4'`, стартуют только posixfs+vsh (net-srv нет), `ping`→«сети нет» — система в ПЕРЕСОБРАННОЙ конфигурации.

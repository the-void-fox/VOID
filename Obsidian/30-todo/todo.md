# VOID — staged роадмап

Принцип: радикальные идеи включаются по одной, **каждая за работающей вехой** — чтобы всегда
было что-то живое в QEMU, а не вечная стройка. Первые ~5 слоёв одинаковы для любого ядра и не
зависят от стержневого тезиса ([[0002-persistent-content-addressed-capability-core]]) — это
чистое «понять, как всё работает». Радикальное начинается со слоя памяти/хранилища.

## Фаза 0 — фундамент (от железа вверх)
- [ ] **Веха 1.** Boot: OpenSBI → entry asm → стек → `kmain`; вывод в UART (NS16550). *(в работе)*
- [ ] **Веха 2.** Trap/прерывания: обработчик исключений, таймерные прерывания (S-mode), `panic` с трассировкой.
- [ ] **Веха 3.** Виртуальная память: Sv39-пагинг, своя карта адресов, переход на виртуальные адреса.
- [ ] **Веха 4.** Kernel heap: физический аллокатор страниц + `#[global_allocator]`, подключить `alloc`.
- [ ] **Веха 5.** Многозадачность: контексты, кооперативный планировщик (потом вытесняющий по таймеру).

## Фаза 1 — стержень (тут начинается VOID)
- [ ] **Веха 6.** Объектная модель в RAM: неизменяемые значения по хэшу + изменяемые ячейки.

- [ ] **Веха 9.** Async-планировщик поверх объектного пространства.
